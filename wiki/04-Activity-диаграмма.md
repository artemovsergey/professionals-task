## Шаг 1. Определяем дорожки — 15 мин

Разделите процесс на дорожки — swimlane. Дорожки показывают, кто отвечает за этап, и делают диаграмму читаемой без легенды.

**Команда**

```bash
Дорожки:
  Мастер            — создаёт заявку, заполняет описание
  Система          — проверяет данные, считает простои, пишет в журнал
  Руководитель     — назначает бригаду, принимает решение по аварийной
  Бригада          — выполняет работы, вносит списание
```

> **Замечание.** Дорожка «Система» — самая ценная: именно на ней видны автоматические проверки, которые эксперт ищет в первую очередь.


## Шаг 2. Рисуем действия и ветвления — 30 мин

Начало — заявка создана, конец — заявка закрыта. Между ними действия и ромбы-решения. Каждому ромбу соответствует явное условие.

**Команда**

```bash
[Заявка создана]
  → Проверить данные заявки          (дорожка Система)
  <Дата окончания раньше даты начала?> → Да → [Отклонить, вернуть мастеру]
  → Запросить бригаду                (дорожка Руководитель)
  → Назначить бригаду
  <Бригада назначена?>                → Нет → вернуться к запросу
```

> **Замечание.** Каждый ромб подписывайте условием, а не номером: «Бригада назначена?» вместо «Решение 1». Иначе диаграмму невозможно читать.


## Шаг 3. Добавляем fork и join — 20 мин

Параллельные действия изображаются чёрной полосой **fork** и **join**. В нашем процессе параллельно выполняются закупка ЗИП и уведомление мастера.

**Команда**

```bash
fork → Параллельно:
        ├─ Проверить наличие материалов на складе
        └─ Уведомить мастера о назначении бригады
join → Работы начаты

→ Зафиксировать фактическое начало
→ Выполнить работы                    (дорожка Бригада)
```

> **Замечание.** Без fork/join диаграмма выглядит последовательной, и эксперт считает, что параллельность не продумана. За это отдельный пункт критерия.


## Шаг 4. Экспортируем и описываем — 15 мин

Экспортируйте в PNG и SVG, допишите раздел в `README.md`: какие требования задания отражает процесс и почему выделены именно эти ветвления.

**Команда**

```bash
app.diagrams.net → File → Export as → PNG (2x) / SVG
# проверить, что все четыре файла на месте
ls -la docs/diagrams/02-activity.*
```

> **Замечание.** В README укажите, что триггер БД (проверка дат заявки) соответствует второму ромбу диаграммы — это связывает проектирование с реализацией.


## Если что-то не получилось

| Симптом | Что делать |
|---|---|
| Стрелки пересекаются и путаются | разнесите действия по дорожкам, каждое строго по горизонтали |
| fork и join выглядят как чёрные прямоугольники | в Draw.io это тонкие полосы — задайте высоту 3 px |
| Диаграмма не помещается по высоте | поверните лист альбомной ориентацией |
| Экспорт в PNG обрезает подписи | экспортируйте с масштабом 2x и полной страницей |
