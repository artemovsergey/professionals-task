# 1. Тестовые данные (110–125 мин)

Создайте `db/seed.sql`. Данные нужны не для красоты: без осмысленных данных
не проверить ни фильтры, ни сводку, ни скриншоты для сдачи. По критериям
чемпионата за тестовые данные в сущностях стоят отдельные баллы.

-- =====================================================================

**Что проверяет этот набор:**

| Данные | Что показывает |
|---|---|
| задачи со всеми четырьмя статусами | фильтр по статусу даёт непустой результат по каждому значению |
| задачи со всеми тремя приоритетами | фильтр по приоритету, сортировка, `byPriority` в сводке |
| `due_date` в прошлом, в будущем и `NULL` | сортировка по сроку и подсчёт `overdue` |
| задача без категории (`category_id IS NULL`) | клиент не должен падать на пустой категории |
| у пользователя 1 — 10 задач | проверка пагинации при `pageSize = 5` |
| задачи пользователей 2 и 3 | проверка изоляции: пользователь 1 не видит чужих |
| «Починить тесты Postman» со сроком 5 дней назад | `overdue` минимум 2 — сводка даёт осмысленный результат |

> **Замечание:** `TRUNCATE ... RESTART IDENTITY CASCADE` — сбрасывает и
> счётчики `BIGSERIAL`, и очищает зависимые таблицы одной командой. Повторный
> запуск `seed.sql` даёт один и тот же результат — это важно для скриншотов и
> для сравнения работы двух участников отбора.

# 2. Сводный запрос (125–135 мин)

Добавьте в конец `db/seed.sql` запрос, который показывает, что сводка будет
работать. Он понадобится в сессии 4 — там же его перенесут в API:

```sql
-- ---------------------------------------------------------------------
-- Сводка по задачам пользователя. Один запрос, без загрузки строк в память.
-- ---------------------------------------------------------------------
SELECT
    COUNT(*)                                              AS total,
    COUNT(*) FILTER (WHERE status = 'done')               AS done,
    COUNT(*) FILTER (WHERE status <> 'done')              AS not_done,
    COUNT(*) FILTER (
        WHERE status <> 'done'
          AND due_date IS NOT NULL
          AND due_date < CURRENT_DATE)                    AS overdue,
    COUNT(*) FILTER (WHERE priority = 'low'    AND status <> 'done') AS open_low,
    COUNT(*) FILTER (WHERE priority = 'medium' AND status <> 'done') AS open_medium,
    COUNT(*) FILTER (WHERE priority = 'high'   AND status <> 'done') AS open_high
FROM tasks
WHERE user_id = 1;
```

Ожидаемый результат для пользователя 1:

```
 total | done | not_done | overdue | open_low | open_medium | open_high
-------+------+----------+---------+----------+-------------+-----------
    10 |    2 |        8 |       2 |        2 |           3 |          3
```

Проверьте себя:

```sql
-- Задачи со сроком в прошлом, которые ещё не выполнены
SELECT id, title, due_date, status
FROM tasks
WHERE user_id = 1
  AND status <> 'done'
  AND due_date IS NOT NULL
  AND due_date < CURRENT_DATE
ORDER BY due_date;

-- Должно вернуть: «Разобраться с РедОС» (сегодня минус 2) и
--                  «Починить тесты Postman» (минус 5)
```

> **Замечание:** `FILTER (WHERE ...)` — стандартный синтаксис SQL для
> условных агрегатов, PostgreSQL 9.4+. Он считает всё в базе: при миллионе
> задач приложение всё равно получит пять чисел, а не миллион строк. Именно
> этот подход переносится в API на странице
> [10-Отметка-выполнения-и-сводка](10-Отметка-выполнения-и-сводка).

# 3. Загрузка данных через DBeaver (135–140 мин)

Скрипт большой, загружать его в DBeaver можно так:

1. Откройте `db/seed.sql` в редакторе (VS Code).
2. Выделите всё: `Ctrl+A`, скопируйте: `Ctrl+C`.
3. В DBeaver откройте окно «SQL Script» (`Alt+Enter` или иконка скрипта).
4. Вставьте и нажмите «Выполнить скрипт» (⚡).

Либо одной командой в терминале:

```bash
psql -h 127.0.0.1 -U taskplanner -d taskplanner -f db/seed.sql
```

# Проверка

```sql
-- 1. Данные загрузились
SELECT count(*) AS users     FROM users;      -- 3
SELECT count(*) AS categories FROM categories; -- 5
SELECT count(*) AS tasks      FROM tasks;     -- 13

-- 2. Согласованность completed_at и status держится
SELECT count(*) AS inconsistent
FROM tasks
WHERE (status = 'done') <> (completed_at IS NOT NULL);
-- 0 — ограничение работает

-- 3. Сводка считается
SELECT * FROM (
  SELECT
    COUNT(*)                                    AS total,
    COUNT(*) FILTER (WHERE status = 'done')     AS done,
    COUNT(*) FILTER (
      WHERE status <> 'done'
        AND due_date IS NOT NULL
        AND due_date < CURRENT_DATE)           AS overdue
  FROM tasks WHERE user_id = 1
) s;
-- 10 | 2 | 2

-- 4. Изоляция видна на уровне данных
SELECT u.email, count(t.id) AS tasks
FROM users u
LEFT JOIN tasks t ON t.user_id = u.id
GROUP BY u.email
ORDER BY u.email;
-- student@college.ru | 10
-- teacher@college.ru |  2
-- second@college.ru  |  1
```

Полезная привычка: перезапускайте `seed.sql` перед каждой работой с
интерфейсом. Тогда скриншоты и результаты проверок воспроизводимы.
