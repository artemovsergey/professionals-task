# Что делаем на этой странице

Наполняем базу осмысленными данными и проверяем, что ограничения из
[03-Скрипт-schema-sql](03-Скрипт-schema-sql) действительно работают. Без
этого не проверить ни фильтры, ни сводку, ни скриншоты для сдачи: пустой
список показывает только «сломанную выгрузку», а не работающий фильтр.

# Шаг 1. Чистим содержимое

```sql
TRUNCATE TABLE tasks      RESTART IDENTITY CASCADE;
TRUNCATE TABLE categories RESTART IDENTITY CASCADE;
TRUNCATE TABLE users      RESTART IDENTITY CASCADE;
```

Сама схема остаётся — очищается только наполнение. `RESTART IDENTITY`
сбрасывает счётчики `BIGSERIAL`, а `CASCADE` чистит зависимые таблицы одной
командой. Без этого повторный запуск скрипта упрётся в `uq_users_email`.

![[images/db04-s1-truncate.png]]
*DBeaver: три TRUNCATE подряд — подготовка к загрузке*

# Шаг 2. Пользователи

```sql
INSERT INTO users (email, password_hash, full_name) VALUES
  ('ivanov@college.ru',   '$2b$10$demo', 'Иван Петров'),
  ('sidorova@college.ru', '$2b$10$demo', 'Мария Сидорова'),
  ('petrov@college.ru',   '$2b$10$demo', 'Пётр Кузнецов');

SELECT id, email, full_name FROM users ORDER BY id;
```

`password_hash` — заглушка, а не настоящий хеш. Реальные пароли заводятся
через API на [07-Регистрация-и-вход-JWT](07-Регистрация-и-вход-JWT), там уже
BCrypt. Для демо-данных хеш не нужен: важно, чтобы в колонке **не лежал**
открытый пароль.

![[images/db04-s2-users.png]]
*Три пользователя, id с 1 по 3 — предсказуемые значения для скриншотов*

# Шаг 3. Категории

```sql
INSERT INTO categories (user_id, name, color) VALUES
  ((SELECT id FROM users WHERE email='ivanov@college.ru'), 'Учёба',  '#4ECC0A'),
  ((SELECT id FROM users WHERE email='ivanov@college.ru'), 'Работа', '#0F9346'),
  ((SELECT id FROM users WHERE email='sidorova@college.ru'), 'Учёба',  '#4ECC0A');

SELECT c.id, c.name, u.email AS владелец
  FROM categories c JOIN users u ON u.id = c.user_id ORDER BY c.id;
```

Обратите внимание: у Иванова и Сидоровой **одноимённые** категории. Так и
должно быть — уникальность на паре `(user_id, name)`, а не на `name`.

# Шаг 4. Десять задач главному пользователю

```sql
INSERT INTO tasks (user_id, title, description, status, priority, due_date, completed_at)
SELECT u.id, t.title, t.description, t.status, t.priority, t.due, t.done_at
  FROM users u
  CROSS JOIN (VALUES
     ('Сделать ER-диаграмму',        'Схема сущностей и связей',         'new',         'high',   CURRENT_DATE + 2,  NULL),
     ('Сверстать главную страницу',  'Список задач, адаптив',            'in_progress', 'medium', CURRENT_DATE + 5,  NULL),
     ('Настроить JWT',               'Регистрация, вход, токен',         'done',        'high',   CURRENT_DATE - 3,  NOW() - INTERVAL '3 days'),
     ('Сходить в спортзал',          NULL,                              'done',        'low',    CURRENT_DATE - 1,  NOW() - INTERVAL '1 day'),
     ('Разобраться с РедОС',         'Код должен запускаться на РедОС', 'in_progress', 'medium', CURRENT_DATE - 2,  NULL),
     ('Подготовить защиту проекта',  'Доклад и демонстрация',            'in_progress', 'high',   CURRENT_DATE + 9,  NULL),
     ('Собрать дистрибутив клиента', 'Инструкция из README',             'in_progress', 'high',   CURRENT_DATE + 4,  NULL),
     ('Собрать мобильный клиент',    NULL,                              'new',         'medium', CURRENT_DATE + 6,  NULL),
     ('Починить тесты CI',           NULL,                              'done',        'medium', CURRENT_DATE - 4,  NOW() - INTERVAL '4 days'),
     ('Сделать скриншоты',           'Для папки docs/screenshots',       'new',         'low',    CURRENT_DATE + 1,  NULL)
  ) AS t(title, description, status, priority, due, done_at)
 WHERE u.email = 'ivanov@college.ru';
```

Сроки заданы выражениями `CURRENT_DATE ± N`, а не датами: набор не устаревает
и через месяц. `completed_at` заполнен только у `done` — иначе сработает
`ck_tasks_completed_at`.

Набор подобран так, чтобы каждый фильтр давал непустой результат:

| Данные | Что показывает |
|---|---|
| все четыре статуса | фильтр по статусу возвращает разное число строк |
| все три приоритета | фильтр по приоритету и сортировка |
| сроки в прошлом, в будущем и `NULL` | сортировка по дате и подсчёт `overdue` |
| `description` у части задач `NULL` | клиент не падает на пустом описании |
| ровно 10 задач | пагинация при `pageSize = 5` видна в две страницы |

# Шаг 5. Задачи других пользователей

```sql
INSERT INTO tasks (user_id, title, status, priority, due_date) VALUES
  ((SELECT id FROM users WHERE email='sidorova@college.ru'), 'Проверить задание коллеги',    'new', 'medium', CURRENT_DATE + 1),

```

# Шаг 6. Ограничение: название из пробелов

```sql
INSERT INTO tasks (user_id, title, status, priority)
SELECT id, '   ', 'new', 'low' FROM users WHERE email='ivanov@college.ru';
```

![[images/db04-s6-title-empty.png]]
*Ограничение сработало: `violates check constraint "ck_tasks_title_not_empty"`*

Заметьте, что `'   '` — не пустая строка. Поэтому в `CHECK` стоит
`length(btrim(title)) > 0`, а не `title <> ''`: без `btrim` пробелы прошли бы
как настоящее название, и в списке появилась бы безымянная задача.

![[images/db04-s6a-still-empty.png]]
*Счётчик задач не изменился — строка не записалась*

# Шаг 7. Ограничение: недопустимый статус

```sql
INSERT INTO tasks (user_id, title, status, priority)
SELECT id, 'Задача с выдуманным статусом', 'archived', 'low'
  FROM users WHERE email='ivanov@college.ru';
```

![[images/db04-s7-bad-status.png]]
*`ck_tasks_status` не даёт записать значение, которого нет в списке*

![[images/db04-s7a-status-check.png]]
*Запрос по `status = 'archived'` возвращает ноль строк*

Это ровно то поведение, которое нужно API: клиент не может записать в базу
статус, которого не знает серверный перечисление, — иначе фильтр по статусу
молча потерял бы такую задачу.

# Шаг 8. Сводный запрос

```sql
SELECT
  COUNT(*)                                                          AS total,
  COUNT(*) FILTER (WHERE status = 'done')                           AS done,
  COUNT(*) FILTER (WHERE status <> 'done')                          AS not_done,
  COUNT(*) FILTER (WHERE status <> 'done' AND due_date IS NOT NULL
                     AND due_date < CURRENT_DATE)                   AS overdue,
  COUNT(*) FILTER (WHERE priority = 'high' AND status <> 'done')    AS open_high
FROM tasks
WHERE user_id = (SELECT id FROM users WHERE email='ivanov@college.ru');
```

![[images/db04-s8-summary.png]]
*Сводка по одному пользователю: 10 всего, 3 выполнено, 1 просрочено*

Один запрос вместо загрузки строк в память: при миллионе задач приложение
всё равно получит пять чисел. `FILTER (WHERE ...)` — стандартный синтаксис
условных агрегатов, PostgreSQL 9.4+. Этот же запрос переносится в API на
[10-Отметка-выполнения-и-сводка](10-Отметка-выполнения-и-сводка).

# Шаг 9. Кто просрочен

```sql
SELECT title, due_date, status FROM tasks
 WHERE user_id = (SELECT id FROM users WHERE email='ivanov@college.ru')
   AND status <> 'done' AND due_date IS NOT NULL AND due_date < CURRENT_DATE
 ORDER BY due_date;
```

![[images/db04-s9-overdue.png]]
*Просрочена одна задача — та, что в работе со сроком два дня назад*

Проверка `status <> 'done'` обязательна: иначе в просроченные попадут задачи,
которые пользователь уже закрыл. Сроки в `CURRENT_DATE ± N` уезжают вместе с
днём — набор перестаёт совпадать с этим запросом через неделю.

# Шаг 10. Выборка только своих задач

```sql
SELECT t.title, u.email AS владелец
  FROM tasks t JOIN users u ON u.id = t.user_id
 WHERE t.user_id = (SELECT id FROM users WHERE email='ivanov@college.ru')
 ORDER BY t.id LIMIT 3;
```

![[images/db04-s10-own-only.png]]
*Только задачи Иванова — тот же фильтр по владельцу, что будет в API*

Это самая важная строка сессии. Изоляция данных начинается здесь: каждый
запрос к `tasks` обязан содержать условие по владельцу. Уберите его — и
пользователь увидит чужие задачи, а тесты из
[25-Тест-кейсы-и-автотесты](25-Тест-кейсы-и-автотесты) с TC-07 упадут.

# Если что-то не получилось

| Симптом | Что делать |
|---|---|
| `409` или нарушение `uq_users_email` при загрузке | забыли `TRUNCATE` или скрипт запускают второй раз без очистки |
| Пробелы в названии проходят | в `CHECK` должно быть `length(btrim(title)) > 0`, а не `title <> ''` |
| `NULL` вместо даты в сортировке | `NULL` в PostgreSQL сортируется последним при `ASC` — добавьте `NULLS LAST` |
| Сводка показывает чужие задачи | забыт `WHERE user_id = …` — это дефект изоляции, а не мелочь |
| Количество задач гуляет между запусками | скрипт выполняется дважды: добавьте `TRUNCATE` в начало `seed.sql` |
| DBeaver выполняет только один оператор | ставьте курсор внутрь нужного оператора и жмите `Ctrl+Enter` |
