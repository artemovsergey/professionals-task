Сессия 3. Web-клиент: сводка, адаптивность, состояния · 95–115 мин

# Что делаем на этой странице

Три вещи, которые отличают готовый интерфейс от черновика: панель сводки,
вёрстка под разные экраны и честные состояния — загрузка, пусто, ошибка,
офлайн.

# Шаг 1. Панель сводки

`src/components/Summary.jsx`:

```jsx
export default function Summary({ summary, today }) {
  if (!summary) return null;

  return (
    <div className="card summary">
      <div className="row">
        <span>Всего задач</span>
        <b className="total">{summary.total}</b>
      </div>
      <div className="row">
        <span>Выполнено</span>
        <b>{summary.done}</b>
      </div>
```

Первой строкой идёт `if (!summary) return null`. Пока сводка не пришла,
панель просто не рисуется — это лучше, чем мигающие нули: пользователь
видит пустое место, а не «у вас 0 задач».

![[images/web18-s1-summary.png]]
*Компонент рисует четыре числа и разбивку по приоритетам*

# Шаг 2. Отметка выполнения

Поставьте галочку у задачи:

![[images/web18-s4-done.png]]
*Задача зачёркнута, счётчик «Выполнено» вырос, сводка пересчиталась*

Один клик делает три вещи: отправляет `PATCH /api/tasks/{id}/complete`,
обновляет строку в списке и перезапрашивает сводку. Если пересчитывать
счётчики на клиенте, они разойдутся с сервером при любом глюке — считать
нужно там же, где считается правда.

# Шаг 3. Адаптивность

Вёрстка перестраивается двумя точками:

```css
@media (max-width: 900px) {
  .content { grid-template-columns: 1fr; }
}
@media (max-width: 560px) {
  .toolbar { flex-direction: column; }
}
```

Ширина в пикселях, а не в процентах от ширины экрана: медиазапросы
описывают конкретные устройства, а не пропорции.

![[images/web18-s2-media.png]]
*Две точки перелома: 900 px — одна колонка, 560 px — фильтры столбиком*

# Шаг 6. Пустое состояние

Введите в поиск то, чего нет:

![[images/web18-s7-empty.png]]
*«Задач по этим условиям нет» и счётчик `всего 0`*

Пустое состояние должно подсказывать, что делать: очистить фильтр или
создать задачу. Молчаливый белый список выглядит как поломка.

# Шаг 7. Ошибка сети

Выключите сеть и попробуйте сохранить задачу:

![[images/web18-s8-offline.png]]
*Метка «офлайн» в шапке и текст «Нет связи с сервером. Проверьте подключение.»*

Текст ошибки приходит из `api.js`: перехватывается сама сеть, а не HTTP-ошибка.
Пользователь должен видеть, что делать: проверить подключение, а не читать
`Failed to fetch`.

> **Замечание:** это состояние не должно заменять данные на экране. Список,
> который уже загружен, остаётся видимым — пропадает только возможность
> сохранить.

# Шаг 8. Ожидание ответа

Нажмите «Войти» при медленной сети:

![[images/web18-s9-loading.png]]
*Кнопка в состоянии «Отправляем…» — действие заблокировано, повторный клик невозможен*

Без такой блокировки пользователь отправит форму дважды и создаст две задачи.
Состояние ожидания обязано быть видно и на кнопке, и на списке при первой
загрузке.

![[images/web18-s10-loaded.png]]
*Через несколько секунд данные пришли — тот же экран уже готов*

# Проверка

| Проверка | Ожидание |
|---|---|
| отметка выполнения | зачёркивание и пересчёт сводки |
| ширина 820 px | сводка под списком |
| ширина 390 px | фильтры столбиком, действия под задачей |
| поиск без совпадений | сообщение о пустом результате |
| сеть выключена | метка «офлайн» и понятный текст |
| медленный ответ | кнопка неактивна, без повторной отправки |
| свежая перезагрузка | пустое место вместо нулей, пока сводка не пришла |

# Если что-то не получилось

| Симптом | Что делать |
|---|---|
| Сводка мигает нулями | нет `if (!summary) return null` — рисуйте панель только после ответа |
| Счётчики расходятся со списком | сводка считается на клиенте вместо серверного `GET /api/tasks/summary` |
| На телефоне горизонтальная прокрутка | у элемента задана фиксированная ширина вместо `max-width: 100%` |
| Медиазапросы не срабатывают | правило объявлено до базовых стилей или в другом файле |
| Фильтры наезжают друг на друга | в мобильном правиле не задан `flex-direction: column` |
| Кнопку можно нажать дважды | нет состояния ожидания и `disabled` |
| Пустой список выглядит как поломка | нет блока «Задач по этим условиям нет» |
| Ошибка сети показывается как HTML | текст ошибки вставили через `innerHTML` вместо React |
