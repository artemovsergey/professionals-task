Сессия 9. Тест-кейсы и автотесты · 90–120 мин

# Что делаем на этой странице

Десять тест-кейсов по шаблону и восемь автотестов по контракту API.
На региональном этапе 2026 за тестирование дают 4,5 %, и проверяют не только
количество, но и то, что тесты действительно ловят ошибки.

# Шаг 1. Шаблон тест-кейса

Один кейс — это предусловие, шаги, ожидаемый результат и приоритет:

```markdown
## TC-01 Регистрация нового пользователя

| | |
|---|---|
| **Предусловие** | пользователь с таким email не зарегистрирован |
| **Шаги** | 1. Отправить `POST /api/auth/register`<br>2. Тело: `{"email":"new-user@college.ru","password":"Password123","fullName":"Иван Петров"}` |
| **Ожидаемый результат** | HTTP `201`, `success = true`, в `data` есть `id`, `email`, `fullName` |
| **Фактический результат** | совпадает |
| **Приоритет** | Высокий |
```

Ожидаемый результат пишется цифрами: код ответа, `error_code`, конкретные
поля. Формулировка «должно работать» не проверяется человеком и тем более
автотестом.

# Шаг 2. Десять кейсов

`docs/testcases/testcases.md`:

| Кейс | Что проверяет | Ожидаемый результат |
|---|---|---|
| TC-01 | регистрация нового пользователя | `201`, пароля в ответе нет |
| TC-02 | повторная регистрация почты | `409`, `error_code = EMAIL_TAKEN` |
| TC-03 | слишком короткий пароль | `400`, `error_code = PASSWORD_WEAK` |
| TC-04 | вход с верным паролем | `200`, в `data` — токен и профиль |
| TC-05 | вход с неверным паролем | `401`, без утечки «почта есть, пароль нет» |
| TC-06 | запрос без токена | `401` в общем формате ответа |
| TC-07 | изоляция: чужой `id` задачи | `403`, а не `404` и не чужие данные |
| TC-08 | недопустимый статус в теле | `400`, задача не создана |
| TC-09 | фильтры, поиск, пагинация | `total` и `items` согласованы, сортировка работает |
| TC-10 | отметка выполнения и сводка | `completed_at` проставлен, счётчики совпадают |

Отдельно стоит разобрать TC-07: `403` вместо `404` говорит, что сервер
знает о существовании чужой задачи. Для изоляции это осознанный выбор — и его
нужно отразить в кейсе, иначе «правильный» ответ неверен.

# Шаг 3. Общий клиент для тестов

`api/TaskPlanner.Tests/ApiTests.cs` начинается не с теста, а с фикстуры —
один `HttpClient` на весь класс:

```csharp
public class HttpClientFixture
{
    public HttpClient Client { get; }

    public HttpClientFixture()
    {
        var baseUrl = Environment.GetEnvironmentVariable("TASKPLANNER_API") ?? "http://api:8080";
        Client = new HttpClient { BaseAddress = new Uri(baseUrl), Timeout = TimeSpan.FromSeconds(30) };
    }
}
```

Адрес берётся из переменной окружения: локально `http://localhost:5099`,
в контейнере — имя сервиса `http://api:8080`. Тесты идут **по живому API**,
а не по мокам: проверяется контракт целиком — HTTP-коды, тела ответов и
настоящий PostgreSQL.

# Шаг 4. Регистрация своего пользователя в каждом тесте

```csharp
private async Task<(string Token, string Email)> SignUpAsync(string prefix)
{
    var email = UniqueEmail(prefix);
    var register = await _client.PostAsJsonAsync(
        "/api/auth/register",
        new { email, password = "Password123", fullName = "Тест Тестов" });
    Assert.Equal(HttpStatusCode.Created, register.StatusCode);

    var login = await _client.PostAsJsonAsync("/api/auth/login", new { email, password = "Password123" });
    Assert.Equal(HttpStatusCode.OK, login.StatusCode);

    var body = await login.Content.ReadFromJsonAsync<JsonElement>();
    return (body.GetProperty("data").GetProperty("token").GetString()!, email);
}
```

Почту с `Guid` в конце — обязательное условие: тесты должны проходить
повторно, на уже заполненной базе. Фиксированный `test@college.ru` сломается
при втором запуске с `409`.

# Шаг 5. Проверяем коды ошибок

```csharp
[Fact]
public async Task Регистрация_повторная_почта_даёт_409()
{
    var email = UniqueEmail("dup");
    var payload = new { email, password = "Password123", fullName = "Тест Тестов" };

    var first = await _client.PostAsJsonAsync("/api/auth/register", payload);
    Assert.Equal(HttpStatusCode.Created, first.StatusCode);

    var second = await _client.PostAsJsonAsync("/api/auth/register", payload);
    Assert.Equal(HttpStatusCode.Conflict, second.StatusCode);

    var body = await second.Content.ReadFromJsonAsync<JsonElement>();
    Assert.Equal("EMAIL_TAKEN", body.GetProperty("error_code").GetString());
}
```

Проверяется не только код, но и `error_code` из
[06-Единый-формат-ответа-и-ошибки](06-Единый-формат-ответа-и-ошибки).
Одно только `Assert.Equal(409, ...)` пропустит ответ, где поменяли текст
ошибки, — а это тоже часть контракта.

# Шаг 6. Проверяем изоляцию данных

```csharp
[Fact]
public async Task Чужая_задача_возвращает_403()
{
    var (ownerToken, _) = await SignUpAsync("owner");
    var owner = AsUser(ownerToken);

    var created = await owner.PostAsJsonAsync("/api/tasks", new { title = "Личная задача" });
    var createdBody = await created.Content.ReadFromJsonAsync<JsonElement>();
    var id = createdBody.GetProperty("data").GetProperty("id").GetInt64();

    var (otherToken, _) = await SignUpAsync("intruder");
    var other = AsUser(otherToken);

    var response = await other.GetAsync($"/api/tasks/{id}");
    Assert.Equal(HttpStatusCode.Forbidden, response.StatusCode);

    var body = await response.Content.ReadFromJsonAsync<JsonElement>();
    Assert.Equal("FORBIDDEN", body.GetProperty("error_code").GetString());
}
```

Два пользователя, один `id`, проверка на чужой. Тест падает, если фильтр по
владельцу исчезнет из запроса, — это ровно та регрессия, которую не ловит
тест «список возвращает 200».

# Шаг 8. Убеждаемся, что тесты падают

Главный признак настоящих тестов — они краснеют, когда код сломан. Временно
уберите фильтр по статусу в списке задач, запустите прогон и убедитесь, что
тесты фильтра упали. Верните код.

```bash
# после правки ожидаем Failed: 1
TASKPLANNER_API=http://localhost:5099 dotnet test
```

Если тест остался зелёным после поломки логики, он ничего не проверяет.

# Если что-то не получилось

| Симптом | Что делать |
|---|---|
| Тесты идут по чужой базе | задайте `TASKPLANNER_API` явно: по умолчанию берётся `http://api:8080` |
| `409` при первом же тесте | в тестах используйте почту с `Guid`, фиксированная почта регистрируется один раз |
| Часть тестов проходит, часть падает на таймауте | поднимите API до старта: `docker compose up -d api`, затем `dotnet test` |
| `error_code` в ответе не найден | нарушен единый формат ответа — см. [06-Единый-формат-ответа-и-ошибки](06-Единый-формат-ответа-и-ошибки) |
| Тест зелёный после поломки кода | в нём нет `Assert` на проверяемое поле — добавьте проверку значения, а не только кода ответа |
