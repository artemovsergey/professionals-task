Сессия 5. Web-клиент: токен и защита маршрутов · 100–150 мин

# Что делаем на этой странице

Кладём токен в `localStorage`, добавляем его в каждый запрос и разбираемся,
что должно происходить, когда токена нет или он недействителен.

Главная мысль страницы: **защита живёт на сервере**. Роутер и условия в React
удобны, но не являются безопасностью — их легко обойти, просто не загрузив
приложение.

# Шаг 1. Хранилище сессии

`web/src/api.js`:

```js
const TOKEN_KEY = 'taskplanner.token';
const USER_KEY = 'taskplanner.user';

export const getToken = () => localStorage.getItem(TOKEN_KEY);
export const setSession = (token, user) => {
  localStorage.setItem(TOKEN_KEY, token);
  localStorage.setItem(USER_KEY, JSON.stringify(user));
};
export const clearSession = () => {
  localStorage.removeItem(TOKEN_KEY);
  localStorage.removeItem(USER_KEY);
};
```

Токен и профиль хранятся **раздельно**. Профиль нужен только для имени в
шапке, поэтому его можно положить рядом открытым текстом — в отличие от
токена, который подписан ключом сервера.

# Шаг 2. Токен уходит в каждый запрос

```js
async function request(method, path, body) {
  const token = getToken();
  let response;
  try {
    response = await fetch(path, {
      method,
      headers: {
        'Content-Type': 'application/json',
        ...(token ? { Authorization: `Bearer ${token}` } : {}),
      },
      body: body === undefined ? undefined : JSON.stringify(body),
    });
  } catch {
    throw new Error('Нет связи с сервером. Проверьте подключение.');
  }
```

Два важных отличия от «просто `fetch`»:

- Заголовок добавляется **внутри** `request()`, поэтому забыть его в
  отдельном компоненте невозможно.
- `catch` вокруг `fetch` ловит обрыв сети и превращает его в понятное
  сообщение. Без него пользователь увидит браузерное «Failed to fetch».

# Шаг 3. Ответ разбирается один раз

```js
if (!response.ok || !payload?.success) {
  const error = new Error(payload?.message ?? `Ошибка ${response.status}`);
  error.code = payload?.error_code ?? String(response.status);
  throw error;
}
return payload.data;
```

Клиенту отдаётся только `payload.data` — без конверта
`{ success, data, message }`. Остальным компонентам не нужно знать про
обёртку, и `success` не проверяется в каждом месте отдельно.

Ошибка получает поле `code` с `error_code` — по нему можно отличить
`EMAIL_TAKEN` от `VALIDATION_ERROR` и показать нужный текст у нужного поля.

# Шаг 4. Вход кладёт токен

```js
login: async (body) => {
  const data = await request('POST', '/api/auth/login', body);
  setSession(data.token, data.user);
  return data.user;
},
```

Запись в хранилище происходит здесь, внутри слоя API. Компонент про
`localStorage` не знает вообще — иначе токен пришлось бы передавать через
каждый проп.

# Шаг 5. Приложение знает, что вошло

```jsx
const [authed, setAuthed] = useState(Boolean(getToken()));
```

Состояние восстанавливается из хранилища при загрузке: перезагрузка страницы
не выкидывает пользователя. Если токена нет — рисуется форма входа, и
никаких запросов за задачами не уходит.

# Шаг 6. Подделанный токен

Впишите в `localStorage` любой мусор в `taskplanner.token` и обновите
страницу. Приложение решит, что пользователь вошёл (токен есть), попробует
загрузить задачи — и получит от сервера `401` с `error_code:
UNAUTHORIZED`.

![[images/web15-s2-fake-token.png]]
*Токен есть в браузере, но подпись не сходится: сервер вернул 401 и клиент вернул форму входа*

Это и есть ответ на вопрос «где тут безопасность». Проверка подписи
происходит на сервере; клиент не может ни подделать токен, ни выдумать
`userId`. Единственное, что клиент контролирует — **показать форму входа
вместо списка**, и то по факту ответа сервера.

# Шаг 7. Выход

```jsx
const signOut = useCallback(() => {
  clearSession();
  setAuthed(false);
  setUser(null);
}, []);
```

Выход очищает хранилище **и** состояние. Забыть вторую часть — типичная
ошибка: интерфейс вернётся к форме, но при перезагрузке список появится
снова.

# Проверка

```bash
# без токена
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:5080/api/tasks
# 401

# с токеном
TOKEN=$(curl -s -X POST http://127.0.0.1:5080/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"email":"ivanov@college.ru","password":"Password123"}' \
  | python3 -c 'import sys,json;print(json.load(sys.stdin)["data"]["token"])')

curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:5080/api/tasks \
  -H "Authorization: Bearer $TOKEN"
# 200
```

# Если что-то не получилось

| Симптом | Что делать |
|---|---|
| После перезагрузки снова форма входа | `setSession` не вызывается в `api.login` либо ключ в хранилище другой в `getToken` |
| Заголовок не уходит | он добавляется в общем `request()`; проверьте, что компоненты ходят через `api.*`, а не напрямую в `fetch` |
| `401` при верном пароле | токен протух (2 часа) — войдите заново и обработайте `401` на клиенте |
| Выйти не помогает | забыт `setAuthed(false)` рядом с `clearSession()` |
| Токен в выдаче Postman | `localStorage` виден на вкладке Application браузера — не отправляйте скриншоты с живым токеном |
