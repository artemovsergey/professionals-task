Сессия 5. Web-клиент: токен и маршруты · 100–150 мин

# 1. Контекст авторизации (100–125 мин)

`src/web/src/auth/AuthContext.tsx`:

```tsx
import {
  createContext,
  useCallback,
  useContext,
  useEffect,
  useMemo,
  useState,
  type ReactNode,
} from 'react';
import { useNavigate } from 'react-router-dom';
import { tokenStorage } from '../api/tokenStorage';
import type { LoginResponse, User } from '../api/types';

interface AuthContextValue {
  user: User | null;
  isAuthenticated: boolean;
  /** Пока читаем токен из хранилища — показываем загрузку, а не редирект. */
  isInitializing: boolean;
  login: (result: LoginResponse) => void;
  logout: () => void;
}

const AuthContext = createContext<AuthContextValue | null>(null);

export function AuthProvider({ children }: { children: ReactNode }) {
  const navigate = useNavigate();

  const [user, setUser] = useState<User | null>(null);
  const [isInitializing, setIsInitializing] = useState(true);

  // При перезагрузке страницы состояние React теряется, а localStorage — нет.
  // Читаем токен один раз при старте.
  useEffect(() => {
    const storedUser = tokenStorage.getUser();
    const token = tokenStorage.getToken();

    // Токен есть, а пользователя нет (например, хранилище правили вручную) —
    // считаем сессию недействительной.
    if (token && storedUser) {
      setUser(storedUser);
    } else {
      tokenStorage.clear();
    }

    setIsInitializing(false);
  }, []);

  const login = useCallback((result: LoginResponse) => {
    tokenStorage.setToken(result.token);
    tokenStorage.setUser(result.user);
    setUser(result.user);
  }, []);

  const logout = useCallback(() => {
    tokenStorage.clear();
    setUser(null);
    navigate('/login', { replace: true });
  }, [navigate]);

  const value = useMemo<AuthContextValue>(
    () => ({
      user,
      isAuthenticated: Boolean(user),
      isInitializing,
      login,
      logout,
    }),
    [user, isInitializing, login, logout],
  );

  return <AuthContext.Provider value={value}>{children}</AuthContext.Provider>;
}

export function useAuth(): AuthContextValue {
  const context = useContext(AuthContext);

  if (!context) {
    throw new Error('useAuth должен вызываться внутри <AuthProvider>');
  }

  return context;
}
```

> **Замечание:** состояние `isInitializing` решает реальную проблему. Без него
> при перезагрузке `user` ещё `null`, защита маршрута сразу бросает на `/login`,
> и пользователь не может попасть на свою страницу даже с действующим токеном.
> «Загрузка → проверили токен → показали или перенаправили» — единственно
> правильный порядок.

> **Замечание:** переиспользуйте `login` из контекста в `LoginPage` и
> `RegisterPage` вместо прямой записи в `localStorage` — тогда состояние React
> и хранилище всегда согласованы. В файлах со страницы 14 замените три строки
> (`setToken`, `setUser`, `navigate`) на:

```tsx
const { login } = useAuth();

// ...
login(result);
navigate('/tasks', { replace: true });
```

# 2. Защита маршрутов (125–140 мин)

`src/web/src/auth/RequireAuth.tsx`:

```tsx
import type { ReactNode } from 'react';
import { Navigate, useLocation } from 'react-router-dom';
import { useAuth } from './AuthContext';

export function RequireAuth({ children }: { children: ReactNode }) {
  const { isAuthenticated, isInitializing } = useAuth();
  const location = useLocation();

  // Пока идёт проверка токена — редирект делать рано
  if (isInitializing) {
    return (
      <div style={{ display: 'grid', placeItems: 'center', minHeight: '100vh' }}>
        <p>Загрузка…</p>
      </div>
    );
  }

  if (!isAuthenticated) {
    // state.from запоминает, куда хотел попасть пользователь,
    // чтобы после входа вернуть его обратно
    return <Navigate to="/login" replace state={{ from: location }} />;
  }

  return <>{children}</>;
}

export function RequireGuest({ children }: { children: ReactNode }) {
  const { isAuthenticated, isInitializing } = useAuth();

  if (isInitializing) {
    return (
      <div style={{ display: 'grid', placeItems: 'center', minHeight: '100vh' }}>
        <p>Загрузка…</p>
      </div>
    );
  }

  // Вошли — на задачи, а не на страницу входа
  if (isAuthenticated) {
    return <Navigate to="/tasks" replace />;
  }

  return <>{children}</>;
}
```

# 3. Шапка с именем и выходом (140–145 мин)

`src/web/src/components/Header.tsx`:

```tsx
import { Link, useNavigate } from 'react-router-dom';
import { useAuth } from '../auth/AuthContext';
import styles from './Header.module.css';

export function Header() {
  const { user, logout } = useAuth();
  const navigate = useNavigate();

  function handleLogout() {
    logout();
    navigate('/login', { replace: true });
  }

  return (
    <header className={styles.header}>
      <Link to="/tasks" className={styles.brand}>Планировщик задач</Link>

      <nav className={styles.nav}>
        <Link to="/tasks">Задачи</Link>
        <Link to="/summary">Сводка</Link>
      </nav>

      <div className={styles.user}>
        <span>{user?.fullName ?? user?.email}</span>
        <button type="button" className="btn-secondary" onClick={handleLogout}>
          Выйти
        </button>
      </div>
    </header>
  );
}
```

# 4. Возврат на нужную страницу после входа (145–150 мин)

В `LoginPage` после успешного входа используйте `location.state.from`:

```tsx
import { Link, useLocation, useNavigate } from 'react-router-dom';

// ...
const navigate = useNavigate();
const location = useLocation();

const from = (location.state as { from?: { pathname: string } } | null)?.from?.pathname;

// после успешного входа:
navigate(from ?? '/tasks', { replace: true });
```

# Проверка

1. Откройте `/tasks` без входа → редирект на `/login`.
2. На `/login` нажмите F5 → остаётесь на `/login`, а не на главной.
3. Войдите → попадаете на `/tasks`.
4. Выйдите через шапку → `/login`, токен удалён из `localStorage`.
5. Войдите снова, откройте `/summary` → шапка видна, страница открылась.
6. Войдите и вручную удалите `taskplanner.token` в DevTools, затем нажмите
   F5 → приложение очистит сессию и вернёт на `/login`.
7. Войдите, откройте DevTools → Network, выполните вход → в каждом запросе
   к `/api/tasks` есть заголовок `Authorization: Bearer eyJ…`.
8. Подождите, пока токен истечёт (или вставьте в `localStorage` мусор) →
   следующий запрос вернёт `401`, интерцептор очистит хранилище и отправит
   на `/login` **сам**, без перезагрузки.

```bash
# проверка, что защита живёт на сервере, а не только в роутере:
# токен в localStorage легко подделать, поэтому 401 должен приходить с API
curl -i http://localhost:5173/api/tasks -H "Authorization: Bearer подделка"
# HTTP/1.1 401 Unauthorized
# {"success":false,"error_code":"UNAUTHORIZED",...}
```

# Если что-то не получилось

| Симптом | Что делать |
|---|---|
| «useAuth должен вызываться внутри AuthProvider» | компонент вне `<AuthProvider>` — проверьте порядок в `App.tsx` |
| При F5 сразу выкидывает на `/login` | нет `isInitializing`, либо его не проверяет `RequireAuth` |
| Цикл редиректов `/login` ⇄ `/tasks` | `RequireGuest` не возвращает `<Navigate>` при входе |
| Токен не уходит в запросах | интерцептор `request` не зарегистрирован или читает не тот ключ |
| После `401` страница не меняется | в интерцепторе `response` нет перехода на `/login` |
| `localStorage` пуст после входа | сохраняли в `sessionStorage` вместо `localStorage` |
| Имя пользователя в шапке не видно | в контексте `user` не обновился — используйте `login` из `useAuth` |
