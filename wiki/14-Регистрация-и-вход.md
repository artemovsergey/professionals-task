# Что делаем на этой странице

Форма входа и регистрации поверх готового `api.js`. Никаких новых запросов:
всё уже описано на [07-Регистрация-и-вход-JWT](07-Регистрация-и-вход-JWT) —
здесь только правильно показать пользователю, что сервер ответил.

# Шаг 1. Два режима одной формы

`web/src/components/AuthForm.jsx` — одна форма с двумя вкладками:

```jsx
export default function AuthForm({ onSignedIn }) {
  const [mode, setMode] = useState('login');
  const [email, setEmail] = useState('ivanov@college.ru');
  const [password, setPassword] = useState('Password123');
  const [fullName, setFullName] = useState('Иван Петров');
```

```jsx
  const [error, setError] = useState('');
  const [busy, setBusy] = useState(false);
```

Один компонент вместо двух — потому что поля совпадают на девять из десяти.
Различие только в одном: у регистрации есть имя, у входа его нет.

Поля заполнены демо-данными, чтобы можно было нажать «Войти» сразу и не
искать пароль в базе.

*Форма входа: две вкладки, почта, пароль и кнопка «Войти»*

# Шаг 2. Отправляем в API

```jsx
const submit = async (event) => {
  event.preventDefault();
  setBusy(true);
  setError('');
  try {
    if (mode === 'login') {
      await api.login({ email, password });
    } else {
      await api.register({ email, password, fullName });
      await api.login({ email, password });
    }
    onSignedIn();
  } catch (e) {
    setError(e.message);
  } finally {
    setBusy(false);
  }
};
```

Два решения:

- **`event.preventDefault()`** — иначе форма перезагрузит страницу и все
  состояние пропадёт.
- **Регистрация сразу с входом.** `POST /api/auth/register` токена не
  возвращает, поэтому после него отправляется `login`. Один клик вместо
  двух — и пользователь сразу попадает в список.

`busy` блокирует повторный клик, пока запрос в полёте: иначе двойное
нажатие даст две регистрации и `409` вместо результата.

# Шаг 3. Неверный пароль

Введите неверный пароль и нажмите «Войти». Текст в `e.message` приходит из
`message` ответа API — клиент не придумывает свои формулировки.

![[images/web14-s2-login-error.png]]

# Шаг 4. Вкладка регистрации

```jsx
{fullName && mode === 'register' ? (
  <label>
    Имя и фамилия
    <input value={fullName} onChange={(e) => setFullName(e.target.value)} />
  </label>
) : null}
```

Поле имени рисуется только в режиме регистрации. При переключении вкладки
форма не перезагружается — значения сохраняются в состоянии компонента.

![[images/web14-s3-register-form.png]]
*Та же форма на регистрации: добавилось поле имени, заголовок вкладки активен другой*

# Шаг 5. После входа — список

`onSignedIn()` переключает приложение:

```jsx
function App() {
  const [user, setUser] = useState(getUser());
  const [authed, setAuthed] = useState(Boolean(getToken()));

  if (!authed) {
    return (
      <AuthForm
        onSignedIn={() => {
          setUser(getUser());
          setAuthed(true);
        }}
      />
    );
  }

  return <TaskBoard user={user} onSignOut={signOut} />;
}
```

Условие `!authed` — единственное место, где выбирается, что показать.
Никаких маршрутов и роутера для двух экранов не нужно.

![[images/web14-s4-board.png]]
*После входа: шапка с именем, список из десяти задач и сводка 10 / 3 / 1*

Список пришёл с токеном — значит, авторизация на клиенте работает. Дальше
он и будет ходить в API с этим токеном, см.
[15-Токен-и-защита-маршрутов](15-Токен-и-защита-маршрутов).

# Если что-то не получилось

| Симптом | Что делать |
|---|---|
| Страница перезагружается при клике | забыт `event.preventDefault()` в обработчике `submit` |
| Ошибка не появляется | `catch` должен читать `e.message` — именно его заполняет `request()` в `api.js` |
| После регистрации снова форма входа | `register` не вызывает `api.login`: токена регистрация не возвращает |
| `Failed to fetch` | dev-сервер не проксирует `/api`; проверьте `server.proxy` в `vite.config.js` |
| Запрос уходит на порт фронтенда | в `fetch` должен быть относительный путь `/api/tasks`, а не полный URL |
