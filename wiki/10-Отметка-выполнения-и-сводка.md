Сессия 2. Backend: отметка выполнения и сводка · 210–260 мин

# Что делаем на этой странице

Два запроса, без которых приложение не работает как задумано:

- **отметка выполнения** — один клик в интерфейсе меняет статус задачи и
  проставляет дату выполнения;
- **сводка** — четыре числа и разбивка по приоритетам для панели сверху.

Сводка — это агрегат по задачам текущего пользователя. Считать её «по всей
таблице» нельзя: чужие задачи попадут в панель, и это сразу провал по
изоляции данных.

# Шаг 1. Отметка выполнения — обработчик

Отдельный метод вместо `PUT`: клиенту не нужно собирать тело задачи целиком,
чтобы поставить галочку.

```csharp
app.MapPatch("/api/tasks/{id:long}/complete", async (
    System.Security.Claims.ClaimsPrincipal user, Data.TaskPlannerContext db,
    long id, Contracts.CompleteTaskInput? input) =>
{
    var task = await db.Tasks.FirstOrDefaultAsync(t => t.Id == id);
    if (task is null) return Api.Fail(404, "Задача не найдена", "NOT_FOUND");
    if (task.UserId != Api.CurrentUserId(user))
        return Api.Fail(403, "Нет доступа к чужой задаче", "FORBIDDEN");

    var done = input?.Done ?? true;
    task.Status = done ? "done" : "in_progress";
    task.CompletedAt = done ? DateTimeOffset.UtcNow : null;
    task.UpdatedAt = DateTimeOffset.UtcNow;
    await db.SaveChangesAsync();
    return Api.Ok(task.ToDto());
}).RequireAuthorization().WithName("CompleteTask").WithTags("Tasks");
```

Две строки здесь нельзя разделять:

- `task.CompletedAt` обязателен при `status = "done"` — ограничение базы
  `ck_tasks_completed_at` отклонит запрос без даты;
- при возврате в работу дата **обнуляется**, иначе ограничение снова ругнётся:
  задача в статусе `in_progress` с непустым `completed_at` нарушает схему.

![[images/api10-s5-code-complete.png]]
*Один метод переключает статус и дату согласованно — обе строки рядом*

# Шаг 2. Ставим галочку

```bash
curl -s -X PATCH http://localhost:5000/api/tasks/10/complete \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"done":true}'
```

![[images/api10-s1-complete-true.png]]
*`200`: статус `done`, `completedAt` заполнен, `updatedAt` обновился*

Посмотрите на `completedAt` — он совпадает с `updatedAt` с точностью до
миллисекунд. Это ожидаемо: обе даты проставляются в одном обработчике.

# Шаг 3. Снимаем галочку

```bash
curl -s -X PATCH http://localhost:5000/api/tasks/10/complete \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"done":false}'
```

![[images/api10-s2-complete-false.png]]
*`200`: статус снова `in_progress`, а `completedAt` — `null`*

Если бы дата выполнения осталась, ограничение базы не дало бы сохранить
такую задачу. Это самая частая ошибка в этом месте.

# Шаг 4. Сводка — обработчик

```csharp
app.MapGet("/api/tasks/summary", async (
    System.Security.Claims.ClaimsPrincipal user, Data.TaskPlannerContext db) =>
{
    var userId = Api.CurrentUserId(user);
    var today = DateOnly.FromDateTime(DateTime.UtcNow);
    var list = await db.Tasks.Where(t => t.UserId == userId).ToListAsync();

    return Api.Ok(new Contracts.TaskSummary(
        list.Count,
        list.Count(t => t.Status == "done"),
        list.Count(t => t.Status != "done"),
        list.Count(t => t.Status != "done" && t.DueDate is not null && t.DueDate < today),
        new Dictionary<string, int>
        {
            ["low"] = list.Count(t => t.Priority == "low"),
            ["medium"] = list.Count(t => t.Priority == "medium"),
            ["high"] = list.Count(t => t.Priority == "high"),
        }));
}).RequireAuthorization().WithName("GetSummary").WithTags("Summary");
```

Разбор четырёх чисел:

| Поле | Что считает |
|---|---|
| `total` | все задачи пользователя |
| `done` | из них выполненные |
| `notDone` | невыполненные |
| `overdue` | невыполненные с просроченным сроком |

Просроченной считается задача, у которой `status <> "done"` **и** `due_date`
раньше сегодняшнего дня. Выполненная просроченная задача просроченной не
считается — её человек уже закрыл.

![[images/api10-s6-code-summary.png]]
*Сводка считается только по задачам текущего пользователя*

порядок в интерфейсе не влияет на расчёт.

# Шаг 6. Сверяем числа с задачами

Сводка — производная от списка, поэтому числа обязаны сходиться:

```bash
curl -s "http://localhost:5000/api/tasks?pageSize=3" \
  -H "Authorization: Bearer $TOKEN"
```

![[images/api10-s4-summary-vs-tasks.png]]
*Сверху — сводка, снизу — первые задачи: `total` совпадает с числом строк*

Если `total` не равно количеству задач в списке, значит фильтр по `user_id`
потерян — сводка считает чужое.

# Шаг 7. Та же сводка на SQL

Проверить расчёт удобно прямо в базе — так видно, что считает СУБД:

```sql
SELECT COUNT(*) AS total,
       COUNT(*) FILTER (WHERE status = 'done') AS done,
       COUNT(*) FILTER (WHERE status <> 'done'
                          AND due_date IS NOT NULL
                          AND due_date < CURRENT_DATE) AS overdue
FROM tasks
WHERE user_id = 1;
```

`FILTER (WHERE ...)` — краткая запись условия внутри агрегата. Без него
пришлось бы писать `SUM(CASE WHEN ... THEN 1 ELSE 0 END)`.

# Проверка

| Проверка | Ожидание |
|---|---|
| `PATCH` с `{"done":true}` | `200`, `status: "done"`, `completedAt` заполнен |
| `PATCH` с `{"done":false}` | `200`, `status: "in_progress"`, `completedAt: null` |
| `PATCH` без тела | `200` и `done: true` — значение по умолчанию |
| `PATCH` чужой задачи | `403`, `FORBIDDEN` |
| `GET /api/tasks/summary` | четыре числа + `byPriority` |
| `total` в сводке и список задач | расходятся — ищите потерю `user_id` |

# Если что-то не получилось

| Симптом | Что делать |
|---|---|
| `500` про `completed_at` | при возврате в работу забыли `CompletedAt = null` |
| `PATCH` возвращает `405` | маршрут должен быть `"{id:long}/complete"`, а тело — необязательное |
| Галочка не снимается | интерфейс шлёт `{"done": false}`, а сервер читает `input?.Done ?? true` — проверьте, что `false` не превращается в `null` |
| `overdue` считает выполненные | в условии пропал `status <> 'done'` |
| `byPriority` пустой | словарь заполняется в коде после запроса — проверьте, что он не перезатирается |
| Сводка показывает чужие задачи | потерян `Where(t => t.UserId == userId)` — это провал по изоляции данных |
| Клиент не видит `byPriority` | ключи `low`/`medium`/`high` задаёт сервер, менять их на клиенте не нужно |
