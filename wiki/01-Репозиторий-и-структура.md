Сессия 0. Подготовка · 15–150 мин

# 1. Репозиторий и первый коммит (15–30 мин)

Сделайте форк репозитория с заданием к себе на GitHub и склонируйте **свой**
репозиторий:

```bash
git clone https://github.com/<ваш-логин>/professionals-task.git
cd professionals-task
```

Настройте пользователя — иначе коммит не пройдёт:

```bash
git config user.name "Иван Петров"
git config user.email "ivan.petrov@college.ru"
```

> **Замечание:** `git config` без `--global` настраивает только этот репозиторий.
> Так вы не меняете настройки других проектов на машине.

# 2. Ветки: одна ветка на сессию (30–45 мин)

Работайте так же, как на чемпионате: каждая сессия — отдельная ветка, в `main`
попадает только проверенное.

```bash
git checkout -b session/1-database
```

Дальше по ходу тренинга:

```bash
git checkout main
git merge --ff-only session/1-database      # проверенное ушло в main
git checkout -b session/2-backend
```

> **Замечание:** `--ff-only` не даёт случайно создать merge-коммит. Если
> `main` ушёл вперёд и fast-forward невозможен — сделайте
> `git rebase session/1-database`, разберите конфликты и продолжите.

Проверка перед первым коммитом:

```bash
git status
git branch
```

# 4. Структура репозитория (60–100 мин)

Создайте папки и заготовки. Команда создаёт и файлы-заглушки, чтобы пустые
папки не потерялись в Git:

```bash
mkdir -p \
  db/erd \
  docs/api docs/testcases docs/uml docs/screenshots \
  postman \
  src/api/TaskPlanner.Api src/api/TaskPlanner.Core src/api/TaskPlanner.Tests \
  src/web src/desktop/TaskPlanner.Desktop src/mobile
```

В каждой папке, где пока нет содержимого, положите `README.md` в одну строку:

```bash
printf 'Backend: ASP.NET Core Web API (.NET 9)\n' > src/api/TaskPlanner.Api/README.md
printf 'Доменный слой: сущности, DTO, сервисы\n'     > src/api/TaskPlanner.Core/README.md
printf 'Тесты xUnit\n'                                > src/api/TaskPlanner.Tests/README.md
printf 'Web-клиент: React 19 + TypeScript + Vite\n'   > src/web/README.md
printf 'Desktop-клиент: Avalonia 11 (MVVM)\n'         > src/desktop/TaskPlanner.Desktop/README.md
printf 'Mobile-клиент: React Native (Expo)\n'         > src/mobile/README.md
```

Итоговая структура:

```

├── .env.example
├── .gitignore
├── .vscode/extensions.json

├── criteria.md
├── db/

│   ├── seed.sql                    ← сессия 1
│   ├── README.md

│   └── mobile/                     ← сессия 8
├── README.md
└── ЗАДАНИЕ.md
```

Создайте `.env.example` — образец переменных окружения. **Сам `.env` в
репозиторий не коммитится.**

```bash
# --- База данных ---
ConnectionStrings__DefaultConnection=Host=127.0.0.1;Port=5432;Database=taskplanner;Username=taskplanner;Password=CHANGE_ME

# --- JWT ---
Jwt__Key=CHANGE_ME_MIN_32_SYMBOLS_FOR_HMAC_SHA256
Jwt__Issuer=taskplanner-api
Jwt__Audience=taskplanner-clients
Jwt__ExpiresInMinutes=60

# --- CORS ---
Cors__AllowedOrigins=http://localhost:5173

# --- Web-клиент (Vite) ---
VITE_API_BASE_URL=/api
```

Скопируйте его в рабочий файл:

```bash
cp .env.example .env
```

> **Замечание:** `Jwt__Key` — это HMAC-ключ, а не пароль. Он попадает в токен,
> поэтому подпись и должна быть им подписана. Ключ короче 32 символов
> вызовет ошибку при старте — `IDX10703: Unable to create keyed hash`. Сгенерируйте:
> `openssl rand -base64 48`.

# 5. Проверка, что секреты не утекут (100–140 мин)

Убедитесь, что `.env` не попадёт в коммит:

```bash
git check-ignore -v .env
```

Должно быть видно правило из `.gitignore`. Если пишет, что файл не
игнорируется — исправьте `.gitignore` сейчас, это самая частая ошибка на
отборе.

Убедитесь, что в истории нет секретов:

```bash
git log --all --full-history -- .env
```

Пустой вывод — хорошо.

# 6. Редактор и форматирование (140–150 мин)

Добавьте `.editorconfig` — он убирает споры о пробелах и табах в репозитории:

```ini
root = true

[*]
charset = utf-8
end_of_line = lf
insert_final_newline = true
trim_trailing_whitespace = true
indent_style = space
indent_size = 2

[*.{cs,csx}]
indent_size = 4

[*.{sql,psql}]
indent_size = 2

[*.md]
trim_trailing_whitespace = false
```

> **Замечание:** `end_of_line = lf` важен для РедОС и Linux — CRLF в файлах
> вызывает проблемы при сравнении и сборке на площадке.

# Проверка

```bash
git status
git branch
ls src/api src/web src/desktop src/mobile db
```

Должно быть: текущая ветка `session/1-database`, файлы `README.md` в папках,
`.env` — в списке `git status` как **неотслеживаемый и игнорируемый**.

# Коммит

```bash
git add .gitignore .editorconfig .vscode .env.example src db docs postman
git commit -m "Настройка проекта: gitignore, структура папок, пример переменных окружения"
```

# Если что-то не получилось

| Симптом | Что делать |
|---|---|
| `git config` просит имя при коммите | заполнить `user.name` и `user.email` |
| `.env` попадает в `git status` как готовый к добавлению | исправить `.gitignore`, сделать `git rm --cached .env` если уже закоммичен |
| `mkdir: cannot create directory` на РедОС | проверить права, использовать `sudo` не нужно — домашняя папка |
| Форк сделал не туда | `git remote -v`, при необходимости `git remote set-url origin https://github.com/<логин>/professionals-task.git` |
