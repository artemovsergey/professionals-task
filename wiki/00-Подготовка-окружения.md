# Что делаем на этой странице

Проверяем, что инструменты установлены и версии подходящие. Один
несовпадающий пункт на площадке стоит часа: проект не собирается, и вы
теряете время на поиск причины вместо работы.

# Шаг 1. Сверяем версии

```bash
dotnet --version
node --version
npm --version
git --version
```

![[images/setup00-s1-versions.png]]
*Все четыре команды ответили: .NET 9.0.318, Node 20.19.2, npm 9.2.0, Git 2.47.3*

Что должно быть:

| Инструмент | Версия | Проверка |
|---|---|---|
| .NET SDK | **9.0** | `dotnet --version` |
| Node.js | 20 LTS+ | `node --version` |
| Git | 2.40+ | `git --version` |
| PostgreSQL | **15+** | `psql -V` |
| DBeaver | 24+ | графическая проверка |
| VS Code или Rider | — | редактор |
| Postman | 10+ | проверка API |

Версии из инфраструктурного листа чемпионата 2026 — РедОС 8.0, .NET 9.0,
Node.js 22.14, Git 2.48, DBeaver 25. Ставьте максимально близко: на площадке
установят именно эти.

Если `dotnet --version` показал 8.0 — у вас старый SDK, и проект из
[05-Проект-API-и-DbContext](05-Проект-API-и-DbContext) не соберётся.

# Шаг 2. Ставим .NET SDK 9

**РедОС 8.0:**

```bash
sudo dnf install -y dotnet-sdk-9.0
```

**Windows:**

```bash
winget install Microsoft.DotNet.SDK.9
```

Проверка после установки:

```bash
dotnet --list-sdks
dotnet --version
```

`--list-sdks` показывает все установленные версии — полезно, когда их
несколько и нужно понять, какая используется по умолчанию.

# Шаг 3. Ставим Node.js

```bash
node --version   # должно быть v20 или выше
npm --version
```

На РедОС 8 ставится Node.js 20 LTS из репозитория. Версия ниже 18 не
подойдёт: Vite 6 требует Node 18+.

# Шаг 4. Поднимаем PostgreSQL

```bash
psql -V
# PostgreSQL 15.x или новее
```

Если сервер установлен, но не запущен:

```bash
sudo systemctl enable --now postgresql
sudo systemctl status postgresql
```

Для проверки без запуска службы достаточно команды из
[03-Скрипт-schema-sql](03-Скрипт-schema-sql):

```bash
psql -h 127.0.0.1 -U taskplanner -d taskplanner -c 'SELECT version();'
```

# Шаг 5. Инструменты для работы

**DBeaver** — графический клиент к PostgreSQL. Именно он используется в
снимках wiki: ограничения из
[04-Тестовые-данные-и-проверка-ограничений](04-Тестовые-данные-и-проверка-ограничений)
проверяются через него.

**Postman** или **Bruno** — для проверки API до написания клиентов. Коллекция
запросов лежит в `postman/` и разбирается на
[24-Документирование-README-и-Postman](24-Документирование-README-и-Postman).

**git.scc** — подсчёт строк кода для отчёта:

```bash
# macOS / Linux
brew install scc
# или
curl -L https://github.com/boyter/scc/releases/download/v3.5.0/scc_3.5.0_linux_amd64.tar.gz | tar xz scc
sudo mv scc /usr/local/bin/

# Windows — скачать релиз
# https://github.com/boyter/scc/releases

scc --version
scc
```

# Проверка

```bash
dotnet --list-sdks && node --version && psql -V && git --version
```

Все четыре команды отвечают — можно начинать с
[01-Репозиторий-и-структура](01-Репозиторий-и-структура).

# Если что-то не получилось

| Симптом | Что делать |
|---|---|
| `dotnet: command not found` | не прописан `PATH`; перезайдите в терминал после установки |
| `dotnet --version` показывает 8.0 | установлен старый SDK, нужен 9.0 — см. шаг 2 |
| `node: command not found` на РедОС | ставьте Node.js 20 LTS и проверьте `PATH` |
| `psql` есть, но не подключается | запустите службу: `sudo systemctl start postgresql` |
| `scc: command not found` | положите файл в `/usr/local/bin` и сделайте `chmod +x` |
