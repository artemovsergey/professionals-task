# Что делаем на этой странице

Закрываем доступ к чужим задачам. Это отдельная страница, потому что
изоляция — самое частое место утечки в учебных проектах: список фильтруют
по `userId`, а вот прочитать задачу по прямой ссылке `/api/tasks/17` обычно
забывают.

# Шаг 1. Откуда сервер знает, кто спрашивает

`Api.CurrentUserId` — единственный источник:

```csharp
public static long CurrentUserId(ClaimsPrincipal user) =>
    long.Parse(user.FindFirst(ClaimTypes.NameIdentifier)!.Value);
```

Идентификатор берётся из токена, который клиент прислал в заголовке
`Authorization`. Подделать его нельзя: подпись проверяется ключом из
конфигурации, а сам ключ на клиенте не лежит.

```bash
# что видит сервер, когда в заголовке токен
echo "$TOKEN" | cut -d. -f2 | base64 -d 2>/dev/null
```

# Шаг 3. Проверка владельца

```csharp
var task = await db.Tasks.FirstOrDefaultAsync(t => t.Id == id);
if (task is null) return Api.Fail(404, "Задача не найдена", "NOT_FOUND");
if (task.UserId != Api.CurrentUserId(user)) return Api.Fail(403, "Нет доступа к чужой задаче", "FORBIDDEN");
return Api.Ok(task.ToDto());
```

Порядок проверок важен: сначала «нет такого `id`» (`404`), потом «не твой»
(`403`). Наоборот получится наоборот — пользователь будет получать `403` на
несуществующие задачи и не сможет отличить опечатку от чужой ссылки.

`403`, а не `404` — осознанный выбор: сервер знает, что задача существует,
но не отдаёт её содержимое. В ТЗ изоляции это соответствует формулировке
«пользователь не должен получать доступ к чужим данным».

# Шаг 4. Список фильтруется, а не проверяется

```csharp
var userId = Api.CurrentUserId(user);
var query = db.Tasks.Where(t => t.UserId == userId);

if (!string.IsNullOrWhiteSpace(status)) query = query.Where(t => t.Status == status);
if (!string.IsNullOrWhiteSpace(priority)) query = query.Where(t => t.Priority == priority);
```

Фильтр по владельцу стоит **первым**, до всех остальных условий. Дальше
`Where` только сужают выборку, и «забыть» их нельзя. Вариант
`ToList()` + фильтрация в памяти вернул бы чужие строки наружу.

# Шаг 5. Проверяем живьём

```bash
python3 tools/api-auth-demo.py | tail -14
```

Скрипт регистрирует двух пользователей, каждый создаёт свою задачу, а затем
один пробует прочитать чужую.

![[images/api08-s2-forbidden.png]]
*403 на чужую задачу, 200 владельцу, 401 без токена и пустой список у второго пользователя*

Четыре ответа сразу, и каждый подтверждает своё правило:

| Запрос | Ответ | Что доказано |
|---|---|---|
| чужой читает чужую задачу | `403` `FORBIDDEN` | содержимое не отдано |
| владелец читает свою | `200` | нормальная работа не сломана |
| список без токена | `401` `UNAUTHORIZED` | маршрут закрыт |
| список второго пользователя | `total = 0` | чужих задач в выдаче нет |

Последняя строка важнее остальных: именно она отражает то, что видит
пользователь, — список, в котором нет чужих задач, а не только ошибка на
чужую ссылку.

# Шаг 6. Изоляция в базе тоже

Фильтр на уровне API можно случайно обойти запросом из другого места.
Поэтому `user_id` остаётся в таблице и в схеме:

```sql
user_id BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE
```

Запросы без условия по владельцу в приложении не появляются: это проверяет
тест TC-07 на [25-Тест-кейсы-и-автотесты](25-Тест-кейсы-и-автотесты) — он
создаёт двух пользователей и читает чужую задачу.

# Шаг 7. Не течёт ли id

Токен содержит `userId` и почту — и больше ничего. Из id нельзя вывести
ничего, чего пользователь не знает о себе, а чужие данные лежат за проверкой
владельца. На clientId не подписываются: подпись делается ключом сервера.

# Если что-то не получилось

| Симптом | Что делать |
|---|---|
| `500` вместо `401` | маршрут без `RequireAuthorization()`, и `CurrentUserId` разыменовывает `null` |
| Чужой список возвращает чужие задачи | `Where(t => t.UserId == userId)` стоит не первым или потерялся при перестройке `query` |
| Все запросы дают `403` | в токене нет `ClaimTypes.NameIdentifier` либо `CurrentUserId` ищет другое имя claim |
| На несуществующую задачу приходит `403` | переставьте проверки: `null` проверяется до сравнения владельца |
| `401` приходит пустым | см. [07-Регистрация-и-вход-JWT](07-Регистрация-и-вход-JWT), шаг с `JwtBearerEvents` |
| Тест с чужим `id` проходит, хотя должен падать | тест сравнивает только код ответа — добавьте `Assert.Equal("FORBIDDEN", …)` |
