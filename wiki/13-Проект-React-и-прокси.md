# Что делаем на этой странице

Поднимаем веб-клиент на React и подключаем его к API. Ключевое решение всей
сессии: браузер не знает адрес API — все запросы идут на `/api` того же
сервера, который отдал страницу. Это и есть прокси Vite.

# Шаг 3. Прокси Vite

`vite.config.js` — самый важный файл проекта:

```javascript
export default defineConfig({
  plugins: [react()],
  server: {
    proxy: {
      '/api': { target: 'http://127.0.0.1:5080', changeOrigin: true },
    },
  },
});
```

Что это даёт:

- в коде клиента пишется `/api/tasks`, а не `http://localhost:5080/api/tasks`;
- в браузере нет кросс-доменных запросов, значит не нужна настройка CORS;
- адрес API меняется в одном месте — в конфиге, а не в двадцати компонентах.

![[images/web13-s4-proxy-code.png]]
*Весь прокси — четыре строки в конфиге*

> **Замечание:** если забыть этот блок, в консоли браузера будет
> `Failed to fetch`, а страница останется пустой. В dev-режиме CORS-ошибка
> видна сразу, поэтому проверяйте консоль при каждом изменении адреса.

# Шаг 4. Точка входа

```html
<body>
  <div id="root"></div>
  <script type="module" src="/src/main.jsx"></script>
```

Пустой `div` — обязателен: React рисует интерфейс внутри него, без контейнера

# Шаг 5. Что рендерится

`src/main.jsx`:

```jsx
function App() {
  const [user, setUser] = useState(getUser());
  const [authed, setAuthed] = useState(Boolean(getToken()));

  if (!authed) {
    return <AuthForm onSignedIn={() => {
      setUser(getUser());
      setAuthed(true);
    }} />;
  }

  return <TaskBoard user={user} onSignOut={signOut} />;
}
```

Одна переменная состояния решает, что показать: форму входа или рабочее
приложение. Проверка идёт по наличию токена, поэтому после перезагрузки
страницы пользователь остаётся внутри — вход заново не требуется.

![[images/web13-s6-main.png]]
*Переключение «форма или список» — две строки состояния*

# Шаг 6. Где живёт токен

`src/api.js`:

```javascript
const TOKEN_KEY = 'taskplanner.token';

export const getToken = () => localStorage.getItem(TOKEN_KEY);
export const setSession = (token, user) => {
  localStorage.setItem(TOKEN_KEY, token);
  localStorage.setItem(USER_KEY, JSON.stringify(user));
};
export const clearSession = () => {
  localStorage.removeItem(TOKEN_KEY);
  localStorage.removeItem(USER_KEY);
};
```

Токен кладём в `localStorage`, а не в переменную модуля: иначе после
перезагрузки страницы приложение снова спросит логин. Пара ключей
вынесена в константы, чтобы «Выйти» удалял ровно то, что положил «Войти».

![[images/web13-s7-session.png]]
*Три функции: прочитать сессию, сохранить и очистить*

# Если что-то не получилось

| Симптом | Что делать |
|---|---|
| Пустая страница без ошибок | проверьте, что в `index.html` есть `<div id="root">` |
| `Failed to fetch` в консоли | не задан `server.proxy` в `vite.config.js` или API не запущен |
| `ECONNREFUSED 127.0.0.1:5080` | API поднят на другом порту — поправьте `target` в прокси |
| `CORS` в консоли | прокси не настроен, запрос ушёл напрямую на другой домен |
| После F5 снова форма входа | токен не сохраняется в `localStorage` |
| «Войти» ничего не делает | смотрите консоль: чаще всего это `VALIDATION_ERROR` или `INVALID_CREDENTIALS` |
| Порт занят | смените `--port` и продублируйте его в `preview` |
