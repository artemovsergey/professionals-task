Сессия 2. Backend: единый формат ответа · 75–150 мин

# Зачем эта страница

Клиенты (web, desktop, mobile) разбирают ответы одинаково. Если один метод
отдаёт «голый» массив, а другой — объект с полями, то в каждом клиенте
появляются частные проверки. За единый формат на всех методах дают баллы.

Формат зафиксирован в [`api/openapi.yaml`](https://github.com/artemovsergey/professionals-task/blob/main/api/openapi.yaml):

```json
{ "success": true,  "data": { }, "message": "OK",    "error_code": null }
{ "success": false, "data": null,  "message": "Задача не найдена", "error_code": "NOT_FOUND" }
```

Два правила, которые проверяют чаще всего:

- `data` есть **всегда** — даже когда это `null`;
- `error_code` записывается в `snake_case`: `VALIDATION_ERROR`, `NOT_FOUND`.

Коды ошибок, которые использует сервис:

| Код | HTTP | Когда |
|---|---|---|
| `VALIDATION_ERROR` | 400 | не прошло проверку полей |
| `UNAUTHORIZED` | 401 | нет токена или он невалиден |
| `INVALID_CREDENTIALS` | 401 | неверная почта или пароль |
| `EMAIL_TAKEN` | 409 | такая почта уже зарегистрирована |
| `FORBIDDEN` | 403 | задача принадлежит другому пользователю |
| `NOT_FOUND` | 404 | сущности нет |

Клиент ориентируется на `error_code`, а не на текст `message`: текст можно
менять, код — нет.

# Шаг 1. Обёртка ответа

`api/TaskPlanner.Api/Contracts/Contracts.cs`:

```csharp
public class Envelope<T>
{
    public bool Success { get; set; }
    public T? Data { get; set; }
    public string Message { get; set; } = "OK";

    [System.Text.Json.Serialization.JsonPropertyName("error_code")]
    public string? ErrorCode { get; set; }
}
```

Один класс на весь API. Имена полей сериализуются в `camelCase`
(`SerializerOptions.PropertyNamingPolicy`), а `error_code` — snake_case,
поэтому у него явная аннотация.

![[images/api05-s14-envelope.png]]
*Класс `Envelope<T>` целиком: четыре поля и одна аннотация*

# Шаг 2. Два хелпера, чтобы не повторять конверт

`api/TaskPlanner.Api/Program.cs`:

```csharp
public static Envelope<T> Envelope<T>(T data) => new()
{
    Success = true,
    Data = data,
    Message = "OK",
    ErrorCode = null,
};

public static IResult Ok<T>(T data) => Results.Json(Envelope(data));
```

`Ok(...)` — единственный способ отдать успех. Так невозможно забыть поле
`error_code` или написать `message` с опечаткой.

![[images/api06-s10-code-helpers.png]]
*Хелперы `Envelope`, `Ok` и `Fail` рядом, в одном месте*

# Шаг 3. Ошибка — тот же конверт плюс код статуса

```csharp
public static IResult Fail(int status, string message, string code) =>
    Results.Json(
        new Contracts.Envelope<object?>
        {
            Success = false,
            Data = null,
            Message = message,
            ErrorCode = code,
        },
        statusCode: status);
```

Клиенту не нужно знать про HTTP-статусы как таковые: он читает `success`,
а по `error_code` решает, показать ли форму входа или сообщение об ошибке.

# Шаг 4. Проверка полей до записи в базу

```csharp
public static List<string> Validate(Contracts.TaskInput input)
{
    var errors = new List<string>();
    if (string.IsNullOrWhiteSpace(input.Title)) errors.Add("title");
    else if (input.Title.Trim().Length > 200) errors.Add("title: максимум 200 символов");

    if (input.Status is not null and not ("new" or "in_progress" or "done" or "cancelled"))
        errors.Add("status");
    if (input.Priority is not null and not ("low" or "medium" or "high"))
        errors.Add("priority");
    return errors;
}
```

Проверка на сервере, а не только в форме: клиент можно вызвать и из Postman,
и из curl.

*`Validate` собирает список проблемных полей, а не падает на первом*

Разница между `403` и `404` осознанная: `403` говорит клиенту «это не твоё»,
`404` — «такого нет». На отборе за изоляцию данных дают баллы, когда чужую
сущность нельзя ни прочитать, ни изменить, ни удалить.

# Шаг 14. Ошибки авторизации пишет сам JWT

Последний кусок формата — ответы 401 и 403, которые ASP.NET отдаёт мимо ваших
обработчиков. Без перехвата клиент получит пустое тело:

```csharp
o.Events = new JwtBearerEvents
{
    OnChallenge = async ctx =>
    {
        ctx.HandleResponse();
        ctx.Response.StatusCode = 401;
        ctx.Response.ContentType = "application/json; charset=utf-8";
        await ctx.Response.WriteAsync(
            "{\"success\":false,\"data\":null,\"message\":\"Нужен Authorization: Bearer <токен>\",\"error_code\":\"UNAUTHORIZED\"}");
    },
    OnForbidden = async ctx =>
    {
        ctx.Response.StatusCode = 403;
        ctx.Response.ContentType = "application/json; charset=utf-8";
        await ctx.Response.WriteAsync(
            "{\"success\":false,\"data\":null,\"message\":\"Недостаточно прав\",\"error_code\":\"FORBIDDEN\"}");
    },
};
```

![[images/api06-s12-code-jwt-errors.png]]
*`OnChallenge` и `OnForbidden` пишут тот же конверт, что и остальные методы*

# Если что-то не получилось

| Симптом | Что делать |
|---|---|
| В JSON `errorCode` вместо `error_code` | проверьте аннотацию `[JsonPropertyName("error_code")]` |
| Поле `data` пропало из ответа | у свойства должен быть тип `T?`, а не `T` без явной инициализации |
| На 401 приходит пустое тело | без `OnChallenge` Kestrel отвечает сам — добавьте обработчик из шага 14 |
| В Swagger вместо `in_progress` — `InProgress` | проверьте, что статус хранится строкой и приходит из базы как есть |
| Кириллица приходит как `\u041f\u0440...` | добавьте `Encoder = JavaScriptEncoder.UnsafeRelaxedJsonEscaping` в `ConfigureHttpJsonOptions` |
| `415 Unsupported Media Type` | не забыли `-H 'Content-Type: application/json'` |
| `401` вместо `403` на чужой задаче | сравните владельца до проверки прав: неавторизованный пользователь должен получать `403`, а не `401` |
