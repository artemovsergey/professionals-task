# Что делаем на этой странице

Список задач — главный экран приложения. Здесь должны быть поиск, три
фильтра, сортировка и пагинация, и всё это должно работать через API, а не
по локальному массиву.

Состояние экрана хранится в одном объекте:

```javascript
const [data, setData] = useState({ items: [], total: 0, page: 1, pageSize: 5 });
const [filters, setFilters] = useState({
  q: '', status: '', priority: '', sort: '', order: '',
  page: 1, pageSize: 5,
});
```

Разделение на `filters` и `data` обязательно: в `filters` лежит то, что выбрал
пользователь, в `data` — то, что пришёл с сервера. Смешивать их нельзя,
иначе счётчик `всего` начнёт показывать длину отфильтрованного массива.

![[images/web16-s1-state.png]]
*Два состояния: параметры запроса и ответ сервера*

# Шаг 1. Любой фильтр сбрасывает страницу

```javascript
const set = (patch) => setFilters((f) => ({ ...f, page: 1, ...patch }));
```

Одна строка решает частую ошибку: если выбрать статус «в работе» на третьей
странице, а подходящих задач всего две, пользователь увидит пустой список.
Сброс `page: 1` после каждого фильтра избавляет от этого.

![[images/web16-s2-set-filter.png]]
*Обновление фильтра всегда возвращает на первую страницу*

# Шаг 2. Панель управления

```jsx
<div className="toolbar">
  <input
    placeholder="Поиск по названию"
    value={filters.q}
    onChange={(e) => set({ q: e.target.value })}
  />
  <select value={filters.status} onChange={(e) => set({ status: e.target.value })}>
    <option value="">Все статусы</option>
    ...
```

Четыре элемента управления подписаны одинаково: изменение любого из них
вызывает `set(...)` и уходит новый запрос. Пустое значение — это «фильтр
выключен», а не «искать пустую строку».

# Шаг 8. Пагинация в коде

```jsx
const pages = Math.max(1, Math.ceil(data.total / data.pageSize));
```

Деление с округлением вверх даёт количество страниц. `Math.max(1, ...)` спасает
от нуля страниц, когда задач нет: иначе в интерфейсе появится «1 / 0».

```jsx
<button disabled={data.page <= 1} onClick={() => setFilters((f) => ({ ...f, page: f.page - 1 }))}>
  Назад
</button>
```

Здесь `page` меняется **без** сброса на единицу — это единственное место, где
пагинация обновляется иначе, чем фильтры.

![[images/web16-s4-pager.png]]
*Кнопки блокируются по краям диапазона страниц*

# Шаг 9. Пустой результат

Введите в поиск фразу, которой нет в задачах:

![[images/web16-s10-empty.png]]
*`Задач по этим условиям нет`, счётчик `всего 0`, пагинация `1 / 1`*

Пустое состояние — это тоже состояние. Без него пользователь видит белый
экран и решает, что приложение сломалось. Сводка справа при этом не меняется:
она считает все задачи, а не отфильтрованные.

# Проверка

| Проверка | Ожидание |
|---|---|
| фильтр по статусу | список и счётчик меняются вместе |
| два фильтра подряд | применяются оба: `in_progress` + `high` |
| поиск по подстроке | находятся задачи со словом внутри названия |
| сортировка «ближайшие» | сроки по возрастанию |
| «Вперёд» на последней странице | кнопка заблокирована |
| фильтр на 2-й странице | список открывается на 1-й странице |
| поиск без совпадений | понятное сообщение, а не пустота |

# Если что-то не получилось

| Симптом | Что делать |
|---|---|
| Счётчик `всего` не меняется при фильтре | он показывает `items.length` вместо `data.total` |
| Фильтр на 2-й странице даёт пустоту | в `set(...)` не сброшено `page: 1` |
| Пагинация показывает `1 / 0` | нет `Math.max(1, Math.ceil(...))` |
| Кнопка «Вперёд» работает на последней странице | забыт `disabled={data.page >= pages}` |
| Поиск ищет только на текущей странице | фильтр не отправляется в запрос — проверьте `q` в строке адреса |
| Сортировка не меняет порядок | пара `поле:направление` не доехала до сервера |
| Список дёргается при вводе в поиск | запрос уходит на каждый символ; добавьте задержку |
| Две страницы показывают одно и то же | не меняется `page` в состоянии |
