Сессия 9. Итоговая проверка · 140–150 мин

Последние 10 минут сессии — не новый код, а проверка того, что всё собрано
работает. Эта страница — чек-лист сдачи.

# 1. Полный прогон с нуля (140–145 мин)

Проверьте ровно то, что сделает проверяющий. Порядок важен: база → API →
клиенты.

```bash
# 1. Чистая база
dropdb -h 127.0.0.1 -U taskplanner taskplanner 2>/dev/null
createdb -h 127.0.0.1 -U taskplanner taskplanner
psql -h 127.0.0.1 -U taskplanner -d taskplanner -f db/schema.sql
psql -h 127.0.0.1 -U taskplanner -d taskplanner -f db/seed.sql

# 2. Backend
cd src && dotnet build
cd api/TaskPlanner.Api && dotnet run &

# 3. Web
cd ../../web && npm install && npm run dev &
```

Пройдите все клиенты и убедитесь, что каждый видит **одни и те же** данные:

| Клиент | Что проверить |
|---|---|
| Web | вход → список → фильтр «Выполненные» → создание задачи → сводка |
| Desktop | вход → список → отметка выполнения → сводка |
| Mobile | вход → список → создание задачи → скриншоты |

Задача, созданная в web, должна появиться в desktop и mobile. Это главный
признак, что все клиенты работают с одним API, а не с локальными копиями.

```bash
# сводка из трёх клиентов должна совпадать
curl -s http://localhost:5000/api/tasks/summary -H "Authorization: Bearer $TOKEN"
```

# 2. Чек-лист по критериям (145–148 мин)

Сверьтесь с [`criteria.md`](https://github.com/artemovsergey/professionals-task/blob/main/criteria.md):

## База данных — 20 баллов

- [ ] `db/schema.sql` в репозитории, выполняется без ошибок
- [ ] две обязательные сущности: `users`, `tasks`
- [ ] ограничения средствами SQL: `NOT NULL`, `CHECK`, внешний ключ, уникальный email
- [ ] индексы на `user_id`, `status`, `due_date`
- [ ] ER-диаграмма соответствует схеме
- [ ] `db/seed.sql` с осмысленными тестовыми данными
- [ ] `db/check_constraints.sql` подтверждает, что ограничения срабатывают

## Backend и API — 25 баллов

- [ ] регистрация и вход, пароль в хешированном виде (BCrypt)
- [ ] токен выдаётся при входе и принимается в `Authorization: Bearer`
- [ ] изоляция данных: пользователь видит и меняет только свои задачи
- [ ] полный CRUD задач
- [ ] отметка выполнения и сводка
- [ ] фильтры, поиск, сортировка, постраничный вывод
- [ ] единый формат ответа на всех методах
- [ ] корректные HTTP-коды: 400 / 401 / 403 / 404 / 500
- [ ] операции логируются

## Web-клиент — 15 баллов

- [ ] 3–4 экрана, все работают через API
- [ ] регистрация и вход, токен сохраняется между перезагрузками
- [ ] адаптивная вёрстка от 360 px до 1920 px
- [ ] фильтры и поиск работают, есть состояния загрузки и «ничего не найдено»
- [ ] понятные сообщения об ошибках

## Desktop-клиент — 15 баллов

- [ ] **настоящее настольное приложение** (Avalonia), не WebView и не обёртка сайта
- [ ] 3–4 экрана: вход, список, сводка, (детали)
- [ ] авторизация и хранение токена между запусками
- [ ] создание, изменение, отметка выполнения, удаление
- [ ] запускается по инструкции из README

## Mobile-клиент — 15 баллов

- [ ] React Native (Expo), запускается на устройстве или эмуляторе
- [ ] 3 экрана, работа с тем же API
- [ ] авторизация, токен сохраняется между запусками
- [ ] создание, изменение, отметка выполнения, удаление
- [ ] скриншоты в `docs/screenshots/`

## Документирование и оформление — 10 баллов

- [ ] `README.md`: как запустить каждую часть, переменные окружения, порты, версии
- [ ] `api/openapi.yaml` соответствует реализации
- [ ] примеры запросов: коллекция Postman с тестами, импорт работает
- [ ] структура репозитория аккуратная, нет мусорных файлов
- [ ] ER-диаграмма, UML-диаграммы, 10 тест-кейсов

# 3. Проверка чистоты репозитория (148–149 мин)

```bash
# 1. Нет ли мусора
git status --short
git ls-files | grep -E "\.(bin|exe|dll|log|user)$|node_modules|/obj/|\.db$|\.dump$"
# должно быть пусто

# 2. Нет ли секретов
git grep -nI "eyJhbGciOi"        # JWT-токены
git grep -nI "Password=.*[^=]$" -- '*.cs' '*.json'   # строки подключения с паролем
git log --all --oneline -- .env  # история .env
```

Если что-то нашлось — исправьте и перезапишите историю:

```bash
# поле .env убрать из истории
git filter-repo --path .env --invert-paths
```

# 5. Проверка на РедОС (после сессии, отдельным заходом)

Это **отдельная задача**, которую стоит сделать до сдачи. Не пропускайте её:
основная ОС на площадке — РедОС 8.0.

```bash
cat /etc/os-release | head -3      # убедиться, что вы на РедОС

dotnet --version                  # 9.0.x
node -v                           # 22.x

# Postgres ставится нативно
sudo dnf install -y postgresql-server
sudo postgresql-setup --initdb
sudo systemctl enable --now postgresql
sudo -u postgres psql -c "CREATE ROLE taskplanner LOGIN PASSWORD 'taskplanner' CREATEDB;"
sudo -u postgres psql -c "CREATE DATABASE taskplanner OWNER taskplanner;"

# Backend
cd src && dotnet build
cd api/TaskPlanner.Api && dotnet run

# Web
cd ../../web && npm install && npm run build     # production-сборка
npm run preview

# Desktop — ключевая проверка: нативный код должен собраться на РедОС
cd ../../desktop/TaskPlanner.Desktop && dotnet build -c Release

# Mobile на РедОС не собирается, только Metro
cd ../../mobile && npx expo start
```

Что может сломаться на РедОС и как чинить:

| Проблема | Причина | Решение |
|---|---|---|
| `dotnet: command not found` | нет SDK 9 | `sudo dnf install dotnet-sdk-9.0`, добавить в `PATH` |
| Node старше 20 | модульная версия | `sudo dnf module disable -y nodejs && sudo dnf install -y nodejs` |
| Сборка React падает | `node_modules` ставились на Windows | удалить `node_modules`, `npm install` заново |
| Avalonia не собирается | нет Linux-зависимостей | `sudo dnf install -y libice6 libsm6 libx11-6` |
| Порт 5000 занят | другой процесс | `ss -tlnp | grep 5000` |
| Файлы с CRLF | редактор на Windows | `sed -i 's/\r$//' файл` или `.gitattributes` с `* text=auto` |
