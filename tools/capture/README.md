# Захват скриншотов и гифок для вики

Вики «ТОиР-Проф» описывает работу по шагам, и каждый шаг подкреплён
иллюстрацией: скриншот в `wiki/images/`, короткая запись в `wiki/gifs/`.
Этот каталог — инструменты, которые делают эти файлы.

Имена файлов задаёт генератор страниц, а не человек: в таблице спринтов
у каждого шага есть поля `png` и `gif`. Итоговое имя получается таким:

| Поле в шаге | Итоговый файл |
|---|---|
| `png="schema-run"` на странице 07 | `wiki/images/07-schema-run.png` |
| `gif="schema-run"` на странице 07 | `wiki/gifs/07-schema-run.gif` |

Проверить, что имя согласовано со страницей, можно так:

```bash
python3 tools/wiki/gen_pages.py --check
```

Скрипт ругается, если два шага претендуют на один и тот же файл.

---

## Установка

```bash
python3 -m pip install --user pillow numpy
```

На РедОС:

```bash
sudo dnf install -y python3-pillow
```

**ffmpeg не нужен.** Запись экрана и сборку GIF делает сам Pillow. Это
осознанно: на площадке чемпионата нельзя рассчитывать, что ffmpeg
установлен, а ставить что-то во время работы некогда.

---

## Что чем делать

| Задача | Инструмент | Когда |
|---|---|---|
| Снять один экран | `rec.py --single` | нужен статичный скриншот: окно DBeaver, Swagger UI, экран приложения |
| Записать выполнение команды | `rec.py --seconds N` | гифка «команда выполняется — вот результат» |
| Выполнить команду и снять экран | `run-page.sh` | шаг из вики, который проверяется командой в терминале |
| Собрать гифку из готовых PNG | `make-gifs.py` | состояния «до / после / ошибка», снятые отдельно |

## rec.py — снимок и запись экрана

Один кадр:

```bash
python3 tools/capture/rec.py --name 16-dbeaver-equipment --single
```

Только часть окна:

```bash
python3 tools/capture/rec.py --name 38-kpi-cards --single --region 0 0 1280 800
```

Запись на 10 секунд:

```bash
python3 tools/capture/rec.py --name 07-schema-run --seconds 10
```

Пауза перед стартом, чтобы успеть переключиться на нужное окно:

```bash
python3 tools/capture/rec.py --name 07-schema-run --seconds 10 --delay 3
```

Остановка в любой момент — `Ctrl+C`: уже снятые кадры всё равно сохранятся.

Полезные аргументы:

| Аргумент | Смысл |
|---|---|
| `--name` | имя файла без каталога и расширения, обязательно |
| `--seconds` | длительность записи, по умолчанию 8 |
| `--fps` | кадров в секунду, по умолчанию 8 (12 и больше — файл быстро растёт) |
| `--delay` | пауза перед стартом записи |
| `--region` | `left top right bottom` — только эта область экрана |
| `--out` | каталог `wiki`, по умолчанию вычисляется от расположения скрипта |
| `--single` | снять один кадр, записать только PNG |

Что скрипт делает сам:

* ужимает кадр до 960 px по ширине — страница открывается и в браузере,
  и в режиме правки, большое изображение «разъезжается»;
* выбрасывает кадры, почти не отличающиеся от предыдущего: экран, на
  котором ничего не происходит, не должен съедать мегабайты гифки;
* приводит все кадры к размеру первого, иначе окно, открывшееся
  посреди записи, ломает анимацию;
* сохраняет GIF (`wiki/gifs/<name>.gif`) и последний кадр как PNG
  (`wiki/images/<name>.png`) — PNG пригодится, если гифка в страницу не нужна.

### Если не снимается

| Симптом | Что делать |
|---|---|
| `не удалось снять экран` | нет `DISPLAY`; запускать из графической сессии, не из-под `sudo` |
| `снимок получился пустым (1x1)` | нет доступа к дисплею: проверьте, что терминал запущен внутри сессии |
| `не установлен Pillow` | `python3 -m pip install --user pillow numpy` |
| `ImageGrab` возвращает чёрный кадр | в некоторых сборках РедОС нужен X11 вместо Wayland: `export XDG_SESSION_TYPE=x11` |

## run-page.sh — команда шага и снимок после неё

```bash
./tools/capture/run-page.sh 07-schema-run psql -h 127.0.0.1 -U toirprof -d toirprof -f db/schema.sql
```

Скрипт выполняет команду, печатает её вывод и код возврата, затем снимает
экран в `wiki/images/07-schema-run.png` и подсказывает, что вписать в
страницу. Код возврата команды не подменяется: если команда упала,
скрипт тоже завершится с её кодом — при `set -e` в `Makefile` или CI это
правильное поведение.

Не нужен снимок:

```bash
NO_SHOT=1 ./tools/capture/run-page.sh 07-seed psql -f db/seed.sql
```

## make-gifs.py — гифка из готовых кадров

```bash
python3 tools/capture/make-gifs.py shots/01.png shots/02.png shots/03.png \
    -o wiki/gifs/11-func-downtime.gif --duration 900
```

Маски тоже работают:

```bash
python3 tools/capture/make-gifs.py 'shots/downtime-*.png' -o wiki/gifs/11-downtime.gif
```

| Аргумент | Смысл |
|---|---|
| `-o`, `--output` | путь к итоговому GIF, обязательно |
| `--duration` | миллисекунд на кадр, по умолчанию 800 |
| `--width` | ширина гифки, по умолчанию 960; `0` — не менять |
| `--colors` | цветов в палитре, 2..256 |

Палитра общая для всех кадров: если у каждого кадра своя, переходы между
ними мерцают разными цветами.

## Порядок работы над страницей

1. Проходите страницу как обычно — с командами и правками.
2. Дойдя до шага, который нужно проиллюстрировать, готовите результат:
   открываете нужное окно DBeaver, Swagger или терминал.
3. Запускаете запись заранее и повторяете действие:

   ```bash
   python3 tools/capture/rec.py --name 07-schema-run --seconds 10 --delay 2
   ```

4. Проверяете результат и вписываете в страницу:

   ```markdown
   ![Таблица equipment в DBeaver](images/07-dbeaver-equipment.png)
   *Ограничения видны во вкладке «Ограничения»*
   ```

5. Имена берёте из таблицы спринтов в `tools/wiki/sprints.py` — не
   придумывайте свои, иначе `--check` покажет расхождение или страница
   останется без картинки.
