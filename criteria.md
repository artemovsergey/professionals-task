# Критерии оценки

Максимум — **100 баллов**.

| Раздел | Баллы |
|---|---|

| 2. Backend и API | 25 |
| 3. Web-клиент | 15 |
| 4. Desktop-клиент | 15 |
| 5. Mobile-клиент | 15 |

Оценивается соответствие тексту задания, а не сложность и не количество написанного кода.

## 1. База данных — 20 баллов

| Критерий | Баллы |
|---|---|
| Скрипт создания таблиц лежит в репозитории и запускается без ошибок | 4 |
| Две обязательные сущности: пользователи и задачи | 4 |
| Ограничения средствами SQL: `NOT NULL`, `CHECK`, внешний ключ, уникальный email | 6 |
| Индексы на ключевые поля (`user_id`, `status`, `due_date`) | 3 |
| ER-диаграмма соответствует реальной схеме | 3 |

*Баллы за сущность «категории» не начисляются — это необязательное дополнение.*

## Частые причины потери баллов

- Desktop-клиент сделан как Electron-обёртка над web-страницей — снимается весь раздел 4 (15 баллов).
- Пароли хранятся в открытом виде или хеш без соли.
- Ограничения проверяются только в коде, а не в базе данных.
- Клиент хранит данные локально и не обращается к общему API.
- Нет инструкции по запуску — проверить работу невозможно.
- В репозитории лежат скомпилированные файлы, дампы базы, ключи и токены.
