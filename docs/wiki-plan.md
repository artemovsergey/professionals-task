# План wiki отбора: пошаговые инструкции к заданию

Внутренний документ организатора. Страницы wiki пишутся строго по этому плану.

## Зачем

Студенту не дают задание «разберись сам». Мы **сами выполняем задание** и
расписываем решение по шагам, с готовым кодом, — как в wiki учебной практики
`StudyPractice-SportStore` и `StudyPractice-SampleApp`.

Одна страница wiki = **одна сессия на 2 часа 30 минут**. К концу сессии в
репозитории лежит рабочий код и сделан коммит.

## Формат страницы (обязательный)

```
- одна страница = одна сессия, номер страницы = номер сессии
- первая строка: что делаем в этой сессии и за сколько минут
- тайминг: разбить сессию на блоки по 10–30 минут, каждый блок — заголовок
- инструкции императивом, на «вы»: «создайте», «проверьте», «запустите»
- готовый код целиком, в блоках, с указанием пути файла
- команды терминала — в блоках ```bash, с пояснением, что делает команда
- > **Замечание** — важные тонкости, ловушки, частые ошибки
- блок «Проверка» — как убедиться, что сессия сделана (команда + ожидаемый вывод)
- блок «Коммит» — сообщение коммита в конце сессии
- без воды, без «в данном уроке мы познакомимся»
- язык — русский, технические термины и код — как есть
```

## Контракт API (общий для всех клиентов, не отклоняться)

Базовый адрес при разработке: `http://localhost:5000`

Обёртка ответа — **везде одинаковая**, snake_case в `error_code`:

```json
{ "success": true, "data": { }, "message": "OK", "error_code": null }
{ "success": false, "data": null, "message": "Задача не найдена", "error_code": "NOT_FOUND" }
```

| Метод | Путь | Коды | Ключевые query-параметры |
|---|---|---|---|
| POST | `/api/auth/register` | 201, 400, 409, 500 | — |
| POST | `/api/auth/login` | 200, 400, 401, 500 | — |
| GET | `/api/tasks` | 200, 400, 401, 500 | `status`, `priority`, `dueDate`, `q`, `sort`, `order`, `page`, `pageSize` |
| POST | `/api/tasks` | 201, 400, 401, 500 | — |
| GET | `/api/tasks/{id}` | 200, 401, 403, 404, 500 | — |
| PUT | `/api/tasks/{id}` | 200, 400, 401, 403, 404, 500 | — |
| DELETE | `/api/tasks/{id}` | 204, 401, 403, 404, 500 | — |
| PATCH | `/api/tasks/{id}/complete` | 200, 401, 403, 404, 500 | — |
| GET | `/api/tasks/summary` | 200, 401, 500 | — |

Значения enum: `status` = `new` | `in_progress` | `done` | `cancelled`;
`priority` = `low` | `medium` | `high`; `sort` = `createdAt` | `dueDate` |
`priority` | `title`; `order` = `asc` | `desc`.

`GET /api/tasks` → `data: { items: Task[], total, page, pageSize }`
`GET /api/tasks/summary` → `data: { total, done, notDone, overdue, byPriority }`
`POST /api/auth/login` → `data: { token, tokenType: "Bearer", expiresIn, user }`
`POST /api/auth/register` → `data: { user }`

Токен: `Authorization: Bearer <token>`. Секрет JWT и строки подключения —
**только через переменные окружения**, в `.gitignore` — `.env`.

## Ограничения по окружению

- **Основная ОС на площадке — РедОС 8.0.** Инструкции по установке даются и
  для Windows (отбор), и для РедОС (проверка на этапе). Запрещено: Windows-only
  пути, `\` в путях, PowerShell-команды, `cmd`, `C:\`.
- На РедОС нет Docker в списке оснащения площадки → **PostgreSQL ставится
  нативно** через `dnf`, не через контейнер. `docker-compose.yml` — только
  для удобства на Windows и как опция.
- Инфраструктурный лист регионального этапа 2026 (стек на площадке):
  РедОС 8.0, .NET 9.0 + Avalonia, Python 3.11, Node.js 22, React Native Tools,
  Flutter 3.29, Electron 35, DataGrip, DBeaver, РЕД База Данных 5, Postman 7,
  Rider 2024.3, WebStorm 2024.3, Android Studio 2024.3.1 + Android 10 SDK.
- Студент тренируется на Windows, но обязан проверить, что проект
  собирается и запускается на РедОС.
