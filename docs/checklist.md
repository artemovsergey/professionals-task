## Демонстрация: порядок показа за 5 минут

1. Войти под `master`, открыть дашборд — показать шесть KPI и индикатор `SSE`.
2. Создать заявку на оборудование, которого нет в эксплуатации — показать отказ.
3. Назначить бригаду, занятую другой заявкой — показать `CREW_BUSY`.
4. Начать работу, списать материал — показать уменьшение остатка.
5. Завершить без причины неисправности — показать сообщение с кодом.
6. Переключиться в веб-клиент, открыть аналитику, выгрузить блок в PDF.
7. Назвать цифры из демонстрационных данных и объяснить, откуда они берутся.

## Что точно спросят и что отвечать

| Вопрос | Короткий ответ |
|---|---|
| Почему ограничения в базе, а не в коде | Иначе правило придётся повторить в двух клиентах, и они разойдутся |
| Зачем триггер, если есть `CHECK` | `CHECK` не видит предыдущее значение и не умеет считать простой |
| Как проверяется работоспособность ограничений | Скрипт `db/verify.sql`: отдельная строка на каждое правило |
| Почему нет миграций | Схема собирается четырьмя SQL-файлами, они читаются как документация |
| Как защищён пароль | Хеш с солью; формат `sha256$` оставлен только для демонстрационных учёток сида |
| Почему нет мобильного клиента | В задании нет отдельного задания и критериев за него; в критериях баллов нет |
| Что делать при потере связи | Клиент показывает последние данные и копит операции в очередь |
