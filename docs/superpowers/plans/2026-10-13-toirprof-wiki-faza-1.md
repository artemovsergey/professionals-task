# ТОиР-Проф — wiki по спринтам, фаза 1 (каркас) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Заменить wiki задания TaskPlanner на wiki системы ТОиР-Проф: 54 пошаговые страницы по 24 спринтам + каркас конвейера захвата скриншотов/GIF + починка публикации в GitHub Wiki.

**Architecture:** Wiki генерируется одним Python-скриптом `tools/wiki/gen_pages.py` из таблицы спринтов, лежащей в том же файле. Это гарантирует единый формат всех 54 страниц, быстрое добавление новых спринтов и отсутствие расхождений между заголовками, навигацией и Home.md. Медиа-конвейер — отдельные скрипты в `tools/capture/`, которые пишут прямо в `wiki/images/` и `wiki/gifs/`.

**Tech Stack:** Python 3 (только stdlib), Bash, Git, GitHub CLI, PostgreSQL 15+, .NET 10, Avalonia 11, React 19 + Vite.

**Spec:** design-сессия brainstorming от 2026-10-13 (структура ниже развёрнута в раздел «Карта спринтов»).

## Global Constraints

- **Язык всей документации — русский.** Имена файлов, коммитов, комментариев и сообщений об ошибках тоже по-русски.
- **Целевая ОС — РедОС 8.0.** В инструкциях запрещены Windows-пути (`C:\`), обратные слэши в путях, `cmd` и PowerShell-команды. Команды — только bash.
- **PostgreSQL ставится нативно через `dnf`**, Docker на площадке может отсутствовать.
- **ИИ запрещён** для кода, SQL, триггеров, функций, архитектуры БД и тестов (Приложение 5, задание 7). ИИ допустим только для текстов документации и презентации.
- **Именование медиа:** `wiki/images/NN-<slug>.png` и `wiki/gifs/NN-<slug>.gif`, где `NN` — двузначный номер страницы (01…54), `<slug>` — латиницей в kebab-case. Один и тот же номер не используется дважды.
- **Именование страниц:** `NN-Заголовок-кириллицей.md`, плоско в `wiki/`, сквозная нумерация 01…54. Плоская структура обязательна — иначе ломаются ссылки GitHub Wiki и Gogs.
- **Относительные ссылки между страницами:** `[Название](Название)` — без `.md`, с кириллицей, как в текущей wiki.
- **Первая строка каждой страницы:** `Спринт N. Название · NN мин` — что делаем и за сколько минут.
- **Заголовки первого уровня** — `#`: `# Что делаем на этой странице`, `# Шаг N. …`, `# Проверка`, `# Если что-то не получилось`, `# Коммит`, `# Навигация`.
- **Иллюстрации** — стандартным markdown `![подпись](images/NN-slug.png)`, не Obsidian-викилинками: так рендерится и в Obsidian, и в GitHub Wiki, и в Gogs.
- **Коммиты** — с префиксом `feat:` / `docs:` / `chore:` / `test:`, на русском, в стиле репозитория.

### Task 1: Генератор wiki-страниц

**Files:**
- Create: `tools/wiki/gen_pages.py`

**Interfaces:**
- Produces: функция `render(sprint: dict) -> str` и словарь `PAGES: list[dict]`; CLI `python3 tools/wiki/gen_pages.py [--out wiki] [--check]`
- Каждая запись в `PAGES`: `{n, title, sprint, task, criteria, points, minutes, intro, result, steps[], checks[], commit, media[], fallback[]}`
- `steps[]`: `{title, minutes, body, files[], code, lang, media[]}`
- `--check` — ничего не пишет, только сверяет: количество страниц, уникальность номеров и имён файлов, отсутствие битых относительных ссылок. Код возврата 1 при расхождении.

- [ ] **Step 1: Написать генератор с данными всех 54 страниц**

Файл `tools/wiki/gen_pages.py` содержит:
1. `HEADER` — хелперы рендеринга (`# Шаг`, `# Проверка`, `# Если что-то не получилось`, `# Коммит`, `# Навигация`).
2. `PAGES` — список из 54 словарей с реальным содержимым: заголовок, спринт, задание Приложения 5, закрываемые критерии с номерами из `05-Критерии-оценки.xlsx`, шаги с таймингом, путями файлов, командами проверки, именами медиа.
3. `SPRINTS` — метаданные спринтов (номер, название, задание, баллы, диапазон страниц).
4. `main()` — записывает `Home.md`, `_Sidebar.md` и 54 страницы, создаёт `wiki/images/.gitkeep` и `wiki/gifs/.gitkeep`.

### Task 3: Медиа-конвейер — захват экрана

**Files:**
- Create: `tools/capture/rec.py`
- Create: `tools/capture/make-gifs.py`
- Create: `tools/capture/run-page.sh`
- Create: `tools/capture/README.md`

**Interfaces:**
- `python3 tools/capture/rec.py --name 07-schema-run --seconds 6 --fps 8 --out ../wiki` — снимает экран через Pillow `ImageGrab`, сохраняет `wiki/gifs/NN-slug.gif` и последний кадр `wiki/images/NN-slug.png`. Возвращает 0, если Pillow не установлен (с понятным сообщением), 1 — если нет дисплея.
- `python3 tools/capture/make-gifs.py shots/07-01.png shots/07-02.png -o wiki/gifs/07-slug.gif` — собирает PNG-последовательность в оптимизированный GIF (adaptive palette, 128 цветов, `optimize=True`).
- `./tools/capture/run-page.sh 07 "db/schema.sql" psql -f db/schema.sql` — выполняет команду, сохраняет её вывод в `wiki/images/NN-console.png` и печатает путь.

- [ ] **Step 1: Написать `rec.py`**

Захват кадра `ImageGrab.grab()`, уменьшение до 960 px по ширине (экономия размера), накопление кадров в список, сборка через PIL `save(..., save_all=True, append_images=..., duration=125, loop=0, optimize=True)`. Аргументы: `--name`, `--seconds`, `--fps`, `--out`, `--region`.

- [ ] **Step 2: Написать `make-gifs.py`**

Принимает список PNG, приводит все кадры к общему размеру (первый кадр), палитру через `Image.ADAPTIVE`, сохраняет GIF. Аргумент `-o` обязателен.

- [ ] **Step 3: Написать `run-page.sh`**

Скрипт принимает номер страницы, подпись и команду. Вывод команды дублируется в `tee`, результат сохраняется в PNG-подложку с помощью `rec.py --single`. Все пути — относительные, синтаксис bash, `set -euo pipefail`.

- [ ] **Step 4: Написать `README.md`**

Таблица «задача → команда», инструкция по установке зависимостей, причина отсутствия ffmpeg и чем она заменена.

- [ ] **Step 5: Проверить синтаксис**

Run: `bash -n tools/capture/run-page.sh && python3 -m py_compile tools/capture/rec.py tools/capture/make-gifs.py`
Expected: обе команды завершаются без вывода
